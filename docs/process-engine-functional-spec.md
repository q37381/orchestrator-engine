## 1 组件定位与边界

### 1.1 是什么

- 嵌入式**流程编排组件库**（jar 形态），由宿主 Spring 容器引入；不是独立服务、不是 Spring Boot Starter。
- 业务方以 **YAML 定义 + SPI 实现** 描述流程；编排语义（顺序、并发、条件、分片、失败收敛、重试、回退、恢复）由引擎承担。
- 一个流程实例在同一时刻只允许一个 owner 驱动；多节点部署下靠数据库状态闸门保证唯一认领。
- 可选能力：后台调度（按路由标签主动认领）、REST 入口（宿主未引入 web 框架时不得影响装配）。

### 1.2 解决的问题

多个业务步骤需要按声明顺序 / 并行 / 条件分支 / 分片展开执行，并同时满足：

- **可观测**：进度、失败摘要、执行历史一眼可查；
- **可干预**：暂停、恢复、停止、整轮重试、定点重跑、人工跳过；
- **可补偿**：Saga 逆序撤销，撤销后可重放恢复现场；
- **可崩溃续跑**：任意时刻崩溃后重新驱动即从断点续跑，不依赖专门的恢复流程。

### 1.3 设计基线

| 基线 | 含义 |
| --- | --- |
| **DB 是真值** | 状态、闸门、进度、交接数据一律落库；内存只承载单次驱动的执行栈，任何本机状态都不得成为判定依据 |
| **声明式编排** | 业务方只写定义与 SPI；顺序/并发/失败收敛/重试/回退等语义不写进业务代码 |
| **至少一次** | 全链路语义为 at-least-once，重复执行安全由动作处理器幂等保证 |
| **不托管事务** | 不使用事务注解、不要求宿主提供事务管理器；一致性靠"先判资格 + 关键写最后 + 全程可重复调用" |

### 1.4 明确不做

| 范围外 | 说明 |
| --- | --- |
| 模板继承 / 跨流程片段复用 | 只保留片段表 DDL，无装载展开机制 |
| 用户会话与鉴权 | 创建人、操作人一律由调用方显式传入，引擎不使用线程本地会话 |
| 业务专表示范 | 校验清单、结论总表等业务表由宿主的处理器/监听器负责 |
| 消息队列、分布式锁、定时调度 | 不做；周期触发属预留 |
| 循环控制节点 | 类型枚举保留，无表达式与策略实现 |
| 系统挂起态的唤醒入口 | 挂起可由动作处理器让渡产生，但本期无唤醒入口 |
| 节点/泳道/动作级跨机认领 | 默认关闭，单 owner 驱动整流程 |
| 心跳与租约 | 预留；owner 崩溃后靠人工重试翻回可认领态 |
| 条件节点的命名后缀 | 语法位占住并明确报错，不静默退化 |

### 1.5 硬性约束

以下硬性契约跨版本、跨宿主生效。实现可以重构，约束不可绕开；其中 `ProcessException` 与 `StringSequenceGenerator` 属于**对外契约类型**，不是内部实现类。

#### 1.5.1 统一异常：ProcessException + 消息键

| 约束 | 要求 |
| --- | --- |
| 异常类型 | 引擎侧业务执行失败必须统一抛 `com.tt.ii.process.exception.ProcessException`；装配/编程期参数校验可用 `IllegalArgumentException`，但不得进入运行期失败摘要 |
| 构造签名 | 只保留 `ProcessException(String messageKey, Object... args)` 与 `ProcessException(String messageKey, Throwable cause, Object... args)`；宿主同名类只需对齐这两个构造即可接管 |
| 消息键 | 形如 `AU204001`，引擎占用 `AU204001` ~ `AU204999`；一键一文案、参数按 `{0}` `{1}` 位置填充 |
| 键可见 | 必须提供 `getMessageKey()` 与 `getArgs()`；`toString()` 必须输出 `类名[键]: 已解析文案`，使日志与 `__error` 摘要都能按码定位 |
| 文案来源 | 默认来自 classpath `/i18n/orchestrator-messages.properties`（UTF-8，简体中文），由异常类懒加载；不声明 Bean、不经容器 |
| 取文案安全 | 键缺失、资源读不到、参数格式错误、外部 resolver 抛异常，一律降级为 `键: 参数...`，绝不因取文案二次抛异常 |
| 文案可替换 | 必须支持 `ProcessException.setResolver((key, args) -> 文案)` 整体替换文案源；返回 null 回落内置 bundle |
| 文案书写 | 文案中不得出现单引号（`MessageFormat` 会吞掉）；需要引号时用中文引号或省略 |

错误码按功能域分段：

| 区间 | 功能域 | 代表键 |
| --- | --- | --- |
| `AU2040xx` | 上下文 | `AU204001` 非分片动作无分片 payload |
| `AU2041xx` | flow DSL 解析 | `AU204101` 尾部多余字符、`AU204107` 节点引用含冒号 |
| `AU2042xx` | 定义装载、聚合展开、段校验 | `AU204204` 容器声明越权字段、`AU204220` action 级段不成对 |
| `AU2043xx` | 物化与驱动 | `AU204302` flow 引用未定义节点、`AU204309` 节点类型重复注册 |
| `AU2044xx` | 计划与定义缓存 | `AU204401` 无已发布版本、`AU204402` 版本不存在 |
| `AU2045xx` | 条件求值 | `AU204501` 非数值操作数不可比较大小 |
| `AU2046xx` | SPI 注册表 | `AU204601` 处理器重名、`AU204611` 分片解析器未注册 |
| `AU2047xx` | JSON | `AU204701` 序列化失败、`AU204703` 反序列化失败 |
| `AU2048xx` | 业务键序列 | `AU204801` 缺少序列 Bean |

新增错误码只能落在对应功能域区间内；跨域占用或复用同键必须视为契约破坏。完整键表以 `src/main/resources/i18n/orchestrator-messages.properties` 为准，本文只列分段与代表键。

#### 1.5.2 业务键：bcs 序列号生成器

| 约束 | 要求 |
| --- | --- |
| 接口 | 必须使用 `com.tt.bb.sequence.StringSequenceGenerator`，唯一方法 `String getStringSequence()`（无参，一次取一个号） |
| 注入方式 | 按 **Bean 名** 匹配，一次性收集上下文中全部该类型 Bean；不写 `@Qualifier`，Bean 名只在一处声明，调用点不重复写字符串 |
| 缺失行为 | 注入必须可选（`required=false`）：零个序列 Bean 时容器仍能启动；取号时缺哪个就抛 `ProcessException("AU204801", Bean名)`，不得回落本地自造号 |
| 唯一性 | 业务键唯一性只由宿主序列保证；同一类两次取号必须不同，撞号由唯一索引暴露；引擎不去重、不改写 |
| 列宽 | 业务键列为 `VARCHAR(32)`；号源格式由宿主决定，引擎不校验、不截断 |
| 宿主接管 | 宿主已有同名接口时，可整份删除引擎替身接口；改 Bean 名只改五类声明一处，调用点不动 |

五类业务键各绑一条序列，不得串号：

| 业务键 | 序列 Bean 名 | 落点 |
| --- | --- | --- |
| 流程实例 | `processInstSequenceGenerator` | `process_inst.proc_inst_id` |
| 节点实例 | `nodeInstSequenceGenerator` | `process_node_inst.node_inst_id` |
| 泳道 | `laneSequenceGenerator` | `process_lane.lane_id` |
| 动作实例 | `actionInstSequenceGenerator` | `process_action_inst.action_inst_id` |
| 回退记录 | `rollbackRecordSequenceGenerator` | `process_rollback_record.rollback_id` |

## 2 抽象层级与命名

### 2.1 层级模型

```text
[定义层]  流程定义 process definition     （YAML/JSON；按 defId + version 不可变）
              │  创建时钉死版本
              ▼
[L1]      流程实例 process instance       （procInstId；一次执行；状态闸门 + 变量空间）
              ├─ [L1.1] 流程调度 process schedule
              │           （可选；schedUnit / schedZone，决定是否参与主动认领）
              └─ [L2]   节点实例 node instance（树；action / parallel / if / group）
                           └─ [L3] 泳道 lane（一个分片键 = 一条泳道）
                                    └─ [L4] 动作实例 action instance
                                              （最小执行单元，绑定一个处理器）
```

**段（segment）不是第五层实例**，而是节点/组回路内的生命周期切面：`setup → main → setdown`；动作还可以再挂一对 action 级段（`action-setup → 动作 → action-setdown`）。

### 2.2 各层职责

| 层级 | 职责 | 关键判定 | 不负责 |
| --- | --- | --- | --- |
| 定义 | 描述形状、策略、守卫、数据交接点；不可变 | 版本 `(defId, version)`；发布态 | 运行期状态 |
| L1 流程实例 | 一次执行的状态闸门、终态聚合、失败摘要、变量空间 | `pending` 可认领；`running` 有 owner | 节点内部编排 |
| L1.1 流程调度 | 路由过滤，决定哪个 worker 主动认领 | 有路由行才参与主动调度 | 状态闸门（仍在流程行） |
| L2 节点实例 | 控制流与容器；冻结策略/守卫；对齐定义表达式 | 类型 + `error_policy` + `condition_expr` | 动作内部业务 |
| L3 泳道 | 承载一个分片键的执行范围；分片节点的一个分片 = 一条泳道 | `(nodeInstId, shardKey)` 唯一 | 跨分片共享（需显式放置） |
| L4 动作实例 | 最小执行单元：守卫、配置、处理器调用、结果落行 | `(nodeInstId, actionDefId, shardKey, segment)` 唯一定位 | 容器收敛 |
| 段 | 生命周期切面：前置、主体、收尾（finally） | `segment` 列；主段参与统计 | 独立拓扑 |

### 2.3 命名体系（含 process 命名）

#### 2.3.1 层级命名对照

| 层级 | 中文名 | 英文/概念名 | 业务键 | 定义键 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 定义 | 流程定义 | process definition | — | `process_def_id` + `version` | 一表多版本；`draft/published/archived` |
| L1 | 流程实例 | process instance | `proc_inst_id` | `process_def_id` + `def_version` | `proc` 是 process 在实例侧的缩写 |
| L1.1 | 流程调度 | process schedule | `proc_inst_id` | — | 可选；`sched_unit` / `sched_zone` |
| L2 | 节点实例 | node instance | `node_inst_id` | `node_def_id` | 树；顶层 `parent_id` 为空 |
| L3 | 泳道 | lane | `lane_id` | — | `shard_key` 为分片键 |
| L4 | 动作实例 | action instance | `action_inst_id` | `action_def_id` | 绑定 `handler_name` |
| 段 | 执行段 | segment | — | — | `setup/main/setdown/action-setup/action-setdown` |
| 回退 | 回退记录 | rollback record | `rollback_id` | — | 关联原动作实例 |

命名规则：

1. **`process` 有三重身份**：产品名、流程层概念名、默认表前缀。三者解耦——表前缀可整体改名（设空则回落裸表名），流程层概念名不变。
2. **定义键与实例键成对**：`xxx_def_id` 是定义侧引用键，`xxx_inst_id` 是运行期业务键；两者不得互相替代。
3. **`proc` 只用于流程实例侧**（`proc_inst_id`）；流程定义侧仍写 `process_def_id`，不混用两种缩写。
4. **业务键统一字符串**；物理自增主键只承载声明顺序与内部定位，不对外暴露。
5. **展示名与引用键分离**：`name` 供视图与日志，`id` 供 flow 引用；改展示名不得动 flow。

#### 2.3.2 持久化命名空间

- 8 张表全部 = **前缀 + 表名**，默认前缀 `process_`：
  `process_definition`、`process_inst`、`process_node_inst`、`process_lane`、
  `process_action_inst`、`process_rollback_record`、`process_fragment`（预留）、`process_sched`。
- 任何一张表都没有"固定名特权"；前缀整体可换，不允许有换不掉的死角。
- 各层持久化的配置桶统一叫 `config`；流程级额外有 `vars`；每层有 `result`；`params` 只是运行期桶，**不建列、不落库**。

#### 2.3.3 状态、类型与段命名

| 类别 | 规范值（落库用小写） |
| --- | --- |
| 运行态 | `created` / `pending` / `running` / `success` / `failed` / `skipped` / `stopped` / `paused` / `suspended` |
| 终态 | `success` / `failed` / `skipped` / `stopped` |
| 节点类型 | `action` / `parallel` / `if` / `group` / `while`（预留） |
| 错误策略 | `fail_fast`（默认）/ `continue_on_error` |
| 执行段 | `setup` / `main` / `setdown` / `action-setup` / `action-setdown` |
| 补偿/重放态 | `compensating` / `compensated` / `compensate_failed` / `blocked` / `restoring` / `restored` / `restore_failed` |
| 发布态 | `draft` / `published` / `archived` |

#### 2.3.4 占位符作用域命名

- **桶前缀**：`vars.` / `params.` / `config.` / `result.`
- **层级锁定前缀**：`process.` / `node.` / `lane.` / `action.`
- 只有以上述前缀开头的占位符才由引擎解析；其余一律视为业务自己的模板语法，原样保留、不报错。
- 注意：`${lane.shardKey}` **不是**受支持的桶路径；分片键应当由动作上下文直接取得，而不是走占位符。

### 2.4 层级不变量

| 编号 | 不变量 |
| --- | --- |
| I1 | **实例树与上下文父链同形**：容器子上下文挂在容器节点上下文上，"取流程级"必须沿父链上溯 |
| I2 | **各层桶相互隔离**：引擎不得自动把下层值写进任何上层桶（无结果上挂、无组内冒泡） |
| I3 | **行与表达式按下标对齐**：实例行按声明顺序（物理主键升序）与定义表达式两两对应 |
| I4 | **实例只存运行期数据**：可由钉死版本定义推导的信息不落实例表；展示快照是唯一例外 |
| I5 | **策略与守卫物化期冻结**：生效错误策略、guard 落到实例行，恢复路径不依赖定义即可判定 |
| I6 | **单 owner + 闸门读库**：一个流程一个 owner；取消/认领判断每步当场读库，不持有本机状态 |
| I7 | **动作终态晚于上层结果**：动作行翻终态/让渡态之前，必须先把该动作显式写入的上层 result（泳道/节点/流程）持久化；上层写失败时不得落成功/跳过，本次驱动失败并重入重跑 |

## 3 功能描述

### 3.1 定义与装载

#### 3.1.1 定义载体与版本

- 定义以 YAML/JSON 文本承载，走安全构造器解析（禁止任意对象实例化），并能承载远超常规大小的定义文本。
- 定义按 `(process_def_id, version)` 定位，**发布后不可变**；流程实例创建时钉死版本，此后驱动、重试、回退都用这一版。
- 创建时只给定义标识则取**最新已发布版**；也可精确指定版本；两者都取不到必须明确报错。
- 同一 `(defId, version)` 只解析一次，缓存规范化快照；每次借出**全新私有副本**（走整体序列化，不手写拷贝），业务代码修改副本不得污染缓存。

#### 3.1.2 流程级声明

| 声明 | 语义 |
| --- | --- |
| `materialization` | 物化时机：`EAGER`（创建期建完整棵节点树）/ `LAZY`（执行到才建，默认） |
| `vars` | 流程级变量初值（可带任意嵌套子包；引擎不认任何保留键名） |
| `flow` | 主流程执行顺序 DSL；顶层逗号即多个根，不包虚拟串行根 |
| `setup` / `setdown` | 前置/收尾**节点引用列表**；`setdown` 为 finally 语义，无论成败都执行 |
| `listeners` | 流程级监听器链（前置可否决，收尾纯通知） |
| `rollbackListeners` | 回退级监听器链（补偿前/后；前置可否决整轮回退） |
| `globalNodeListeners` / `globalActionListeners` | 全局节点级/动作级链：声明一次，对每个节点/动作生效，与本地链合并时全局在前、不去重 |
| `errorPolicy` | 全局错误策略；节点未声明时回落，节点自己的声明优先（单值覆盖） |
| `autoRollback` | 自动回退开关：驱动终态为 `failed/stopped` 时收尾后自动补一轮逆序补偿 |
| `settleOnStop` | 停止先收尾开关：停止走两阶段，先落标识，下一轮调度补跑收尾段后才落 `stopped` |
| `repeatSegments` | 段"每趟驱动重跑"开关（流程级）；默认关闭，走成对重臂语义 |
| `nodes` | 节点声明表（键 = 定义 id = flow 引用键） |

所有段均可省略；"写了但留空"必须与"整段缺失"同口径。

#### 3.1.3 节点声明

| 属性 | 语义 |
| --- | --- |
| `name` | 展示名；未声明回落定义 id |
| `handler` | 单动作节点的处理器名（等价于一条动作） |
| `actions` | 节点内多动作序列（与 `handler` 二选一，声明了 `actions` 即优先） |
| `setup` / `setdown` | 节点回路内的前置/收尾**内联动作序列**（与 `actions` 同构；`setdown` finally 恒执行） |
| 组级段 | 聚合节点可在组声明内或节点同级写 `setup` / `setdown`：字符串列表 = 叶子子节点引用，动作列表 = 内联动作；两处等价、不可混用 |
| `group` | 聚合节点声明：`flow` + `nodes`（装载期展开为命名串行容器） |
| `shard` | 分片解析器名；非空即分片节点 |
| `laneExecution` | 泳道串/并行（默认串行） |
| `actionExecution` | 节点内动作序列串/并行（默认串行） |
| `when` | 节点级声明式守卫；假则整节点跳过 |
| `errorPolicy` | 节点级错误策略（覆盖全局） |
| `config` | 业务配置桶（物化期解析并冻结） |
| `listeners` | 节点级监听器链 |
| `repeatSegments` | 段重复执行开关（节点级/组级） |
| `segmentsFollowShard` | 节点级段是否跟随分片（仅分片叶子；默认 `true`） |

#### 3.1.4 动作声明

| 属性 | 语义 |
| --- | --- |
| `id` | 节点内唯一引用键 |
| `name` | 展示名；未声明回落 id |
| `handler` | 处理器名（按名字路由） |
| `when` | 动作级声明式守卫 |
| `config` | 动作级业务配置桶 |
| `listeners` | 动作级监听器链 |
| `setup` / `setdown` | action 级段（仅主段动作可挂，必须成对，深度锁 1） |

#### 3.1.5 段声明

| 宿主 | 段形态 | 语义 |
| --- | --- | --- |
| 流程 | `setup` + `flow` + `setdown` | 三段式；`setdown` 为 finally，无论主段成败都执行 |
| 叶子节点 | `setup` + `actions`/`handler` + `setdown` | 节点回路三段；分片节点默认**每泳道**各一套回路 |
| 聚合节点 | 组 `setup` → 子节点序列 → 组 `setdown` | 段包住整个子节点序列；组无 MAIN 动作段 |
| 动作 | action `setup` → 动作 → action `setdown` | 成对声明；用于成对的前置/收尾副作用 |

`repeatSegments: true` 表示"每趟驱动重跑段"；默认关闭时走**成对重臂**：现场被收尾撤除后重入，按"setup 已成功、setdown 未跑"或"setdown 已跑、主体需重跑"成对补跑。

`segmentsFollowShard: false`（仅分片叶子）表示节点级段不跟随分片：setup 一次 → 各泳道主体 → setdown 一次，段行 `lane_id` 恒为空；动作级段恒随主体逐泳道。

段不进 flow DSL，仅存在于宿主内部；段行以 `segment` 列区分，主段参与进度统计与回退扫描，段行只在明细中可见、不参与补偿。

#### 3.1.6 flow DSL

```text
flow     := item ("," item)* [","]
item     := leaf | parallel | if | group
leaf     := nodeRef
parallel := "PARALLEL" [":" name] "(" item ("," item)* [","] ")"
if       := "IF" "(" condition "," item ["," item] [","] ")"
group    := "GROUP" ":" name "(" item ("," item)* [","] ")"
```

示例：

```text
fetchTopology, preCheck, PARALLEL(migrateData, buildIndex), postCheck,
IF(${vars.dialect}=='goldendb', gdbVerify, mysqlVerify)
```

规则：

- 顶层逗号 = 平级根，按声明顺序串行驱动；不生成虚拟串行根。
- `PARALLEL(...)` 子项全部扇出并发；`IF(cond, then[, else])` 只驱动选中支；`GROUP:名(...)` 为命名串行容器。
- **命名写在关键字与括号之间**：`PARALLEL:checks(a,b)` 的名字指向节点表下的纯容器声明，于是并行容器也能就近携带策略、守卫、配置、节点级监听器；`GROUP` 的组名必须写。
- 冒号是保留字符：只允许出现在关键字后作为命名后缀；节点引用中出现冒号必须拒绝。
- 空白不敏感（含换行与 CRLF）；容器子项与整条 flow 的尾随逗号一律当收口，真正的空项（`a,,b`）仍拒。
- 语法必须**往返互逆**：文本可解析成表达式树，表达式树可写回等价文本（聚合节点展开依赖这一点）。

#### 3.1.7 聚合节点展开

- `nodes.<key>.group` 声明一个"对外一个名字"的命名串行容器；装载期把组内子节点提升进顶层节点表（键带组名前缀），并把 flow 中的组名重写为 `GROUP:名(子1,子2,...)`。
- 组可嵌套，深度有上限；子节点键不得与既有键冲突；不得跨组引用另一个顶层聚合节点。
- 展开结果必须落在可序列化字段里（定义快照只存 flow 文本，展开结果不能只放内存）。

#### 3.1.8 装载期校验（宁拒不猜）

| 校验点 | 要求 |
| --- | --- |
| DSL 语法 | 多余字符、缺括号、缺节点引用、非法位置必须当场拒并带位置信息 |
| 命名配对 | 命名并行后缀必须在节点表有对应声明；声明了容器属性却未被任何 flow 引用（死配置）必须拒 |
| 纯容器约束 | 命名并行不得声明 handler/actions/shard/执行档/段；聚合节点另允许组级段 |
| 命名容器空子项 | 命名并行与聚合节点无子项必须拒 |
| 段形状 | 叶子段只接受内联动作；组级段按声明形状分流（引用或内联）；一条里混用必须拒 |
| 段成对 | action 级段必须成对；段动作不得再挂段（深度锁 1） |
| 段死配置 | 开了 `repeatSegments` 却没有任何段；开了 `segmentsFollowShard: false` 却不能/没有分片，必须拒 |
| 枚举与开关 | 物化时机、错误策略、布尔开关的非法声明值必须拒；合法值归一化后入库 |
| 早失败优先 | 用户手写的名字/开关配错一律装载期拒；只有运行期才能判定的语义（如 flow 引用未定义节点）可延迟到驱动期，但必须落到实例行的失败摘要 |

### 3.2 流程（process）

#### 3.2.1 创建

- 创建流程实例：落 `pending`，返回流程实例业务键（`proc_inst_id`）。
- 创建参数进流程级 `config` 桶；定义 `vars` 与创建参数合并为初始变量空间。
- 创建人由调用方显式传入；不传则不记创建人。引擎不读取会话、不使用线程本地上下文。
- 可选路由：给了服务单元才写调度行，才参与主动调度；未给则不写——仍可同步触发。
- 物化按定义 `EAGER/LAZY` 执行：`EAGER` 创建期建完整棵**节点**树（进度分母稳定），`LAZY` 执行到才建；泳道与动作行一律驱动期按需创建。

#### 3.2.2 启动与认领

- 启动以比较交换把流程从 `pending` 翻 `running`，取得唯一驱动权；抢不到不报错，只回报当下状态。
- 已非 `pending`、行不存在、被别的 owner 抢先，均不抛异常；返回当下状态。
- 一个流程由一个 owner 走查驱动整棵树；流程内并发由 owner 用自己的池铺开。
- 执行类入口返回"流程实例 id + 调用结束时的状态"；坏终态（`failed/stopped`）附一条失败摘要；不承诺一定是终态，不造假状态，查不到行即空状态。

#### 3.2.3 驱动顺序与 finally

- 顶层按 **`setup` → `flow` → `setdown`** 顺序驱动；`setdown` 具备 finally 语义：无论主段成败都执行，其结果参与终态聚合。
- 例外：动作处理器让渡导致本轮退出时，`setdown` 不跑；重入完成后再收尾。
- 序列收敛：根序列遇坏是否叫停，**就近声明优先**——坏的那一项自己声明过就听它的，没声明才回落本层策略；容器内部收敛只看容器自己那一条，子项声明不得跨层。
- 执行顺序清单必须按 `setup + flow + setdown` 前序展开（容器在前、子节点紧随），不得把节点表书写顺序当执行顺序。

#### 3.2.4 终态与失败摘要

- 流程终态按严重程度取最差：`failed > stopped > success/skipped`；`skipped` 与 `success` 都算完成且不拦后续。
- 让渡感知：坏终态优先 > 让渡 > 严重程度聚合，退让信号不得被吞成成功。
- 失败摘要分层留痕：动作行与节点行各记自己那条；流程行只记本次驱动的**首条**（并行同炸只留最先那句）。
- 坏终态才把流程级摘要落进 `result` 的保留键 `__error`；好终态必须反向摘掉上一轮残留。
- 定义都取不出这类"还没铺开就失败"的路径也必须兜底落库并翻终态，不能让流程僵在 `running`。

#### 3.2.5 让渡与重入

- 动作处理器返回 `pending` / `paused` / `suspended` 之一 = **让渡**：本轮立即退出驱动——收尾段与后续根不跑、剩余项不 drain、容器不落终态、不发收尾监听；流程行落该状态等重入。
- `pending` 由调度重捞；`paused` 走恢复入口；`suspended` 停驻（本期无唤醒入口）。
- 坏终态（失败/停止）优先于让渡：已失败就按现状收尾，不让渡。
- 重入时：已落终态的节点行与动作行直接跳过；非终态行属让渡/中断残留，重入重跑（至少一次）。这就是断点续跑的全部机制，不引入第二套恢复语义。
- 非法返回值（`created`/`running` 这类非终态且非让渡）一律兜底归一为 `failed`，不得静默过聚合。

#### 3.2.6 停止（硬停与先收尾）

- **硬停**（默认）：停止即落 `stopped`，只翻闸门，不强中断正在跑的任务。
- **先收尾**（`settleOnStop: true`）：停止入口只写停止标识并返回受理成功；下一次调度进入**收尾轮**——只补跑收尾段/收尾节点、不推进主链，收尾轮结束才落 `stopped`（收尾真失败才落 `failed`）。
- 策略在创建期由流程实例钉死，停止与驱动只读流程行，不依赖定义装载；未钉（未声明/旧行）= 硬停。
- 终态（已 `success/failed/stopped/skipped`）上一律返回 false。

#### 3.2.7 自动回退与重放

- `autoRollback: true` 时，本次驱动终态为 `failed/stopped`，在收尾（落终态 + 发完流程收尾监听器）之后自动补一轮逆序补偿；`paused` 不触发；回退异常不得改写调用方拿到的终态。
- 重放（恢复现场）：流程若回退过，在重新驱动前、流程前置监听器之后，按执行顺序**正序**把被撤销的副作用重新施加回来；失败则落 `failed` 挂起、不向前驱动，且**刻意不触发自动回退**（上一轮补偿已做过，现场没立稳再撤销只会更乱）。
- 重放只接在重新驱动的唯一汇聚点；从未回退过的流程只多一次空查询即返回。

#### 3.2.8 调度与多节点

- 调度能力：按池剩余容量限量认领、批量捞取、认领后异步驱动；可禁用改为同步触发。
- 分布式路由：按"服务单元 + 可选网络区域"过滤认领范围；未路由的流程不被主动认领（仍可同步触发）；无路由配置时保持全局捞取。
- 调度器为**可选项**：当前默认装配不注册调度器 Bean，需要主动调度的宿主必须显式装配；不装配不影响同步执行。
- 单 owner 模型下 owner 崩溃会留下执行中的僵持流程，必须由人工干预（重试）翻回可认领态；租约/心跳属预留能力。

### 3.3 节点（node）

#### 3.3.1 类型与行为

| 类型 | 行为 |
| --- | --- |
| `action` | 叶子：单 `handler` 或节点内多动作序列；可声明分片；串/并行由 `actionExecution` 决定 |
| `parallel` | 并行容器：子项全部扇出、join 聚合；匿名并行吃全局策略；命名并行（`PARALLEL:名`）可携带自己的策略/守卫/配置/监听器 |
| `if` | 条件容器：`then` + 可选 `else`；决策（`__chosen`）持久化，恢复时复用不重算；未选支不驱动，但在选中支之后补一行**已跳过**的节点行留痕（`__skipReason=BRANCH_NOT_TAKEN`），并记录 `__skippedBranch`；无分支可走判 `skipped`（控制流等价成功） |
| `group` | 聚合节点：命名串行容器，子表达式按声明顺序逐个走查；组级守卫/策略/配置/监听器/段；组桶共享靠**显式放置**，引擎不自动冒泡 |
| `while` | 预留，无表达式与策略实现 |

#### 3.3.2 类型归口

一种节点类型的"怎么建行"与"怎么跑"必须归在同一份类型档案里；新增节点类型 = 新增表达式 + 新增一份档案并注册，不改既有分发。物化按表达式类分发、驱动按行上类型分发，两处分发必须同源（一次注册）；类型不识别要明确报错，同一类型被两份档案认领要在装配期拒绝。

#### 3.3.3 守卫（guard）

- 节点级 `when` 假 → 整节点 `skipped`；聚合节点与命名并行同口径；匿名并行/IF 无声明可挂，不参与 guard。
- 动作级 `when` 假 → 该动作 `skipped`，`__skipReason=GUARD_FALSE`。
- IF 的 `condition_expr` 装的是**分支选择条件**，不是"要不要跑"的守卫，不走同一判定。

#### 3.3.4 物化与对齐

- 两档时机：`EAGER` 创建期建完整棵**节点**树；`LAZY` 执行到才建（默认）。两种模式下驱动路径必须一致。
- 例外：**IF 分支恒为惰性**——选哪支要到驱动期决策才算得出，`EAGER` 也不预建分支，避免留下永远未被执行的孤儿行；未选支留痕行是已跳过的终态行，不在此约束内。
- 节点行必须把**生效错误策略**（自己声明 > 全局 > 默认）、guard、业务配置、定义引用键与展示名快照烙进行。
- 实例行与定义表达式按声明顺序两两对齐：已存在行复用、缺行用手里正在走的表达式补建（不做路径反查）。
- 对齐时把定义表达式、节点定义、生效监听器链挂到实例行的非持久化字段上；此后驱动与类型档案一律行内自取，不再回查定义。
- 半物化愈合：崩溃或异常导致只建了一部分行时，重新驱动必须按需补齐缺行，不重复建、不改变已有拓扑顺序。
- 子层时机：泳道与动作行一律驱动期按需创建（两档相同），不得创建期预建，避免永远未执行的孤儿行。

### 3.4 泳道（lane）

- 节点声明分片解析器名即成为分片节点；一个分片键对应一条泳道，泳道是动作的容器。
- 两阶段解析：解析全部分片键（驱动期现解，每次可重解，要求幂等稳定）+ 按分片键现场重建强类型负载（不落库）。
- 解析入参是节点上下文：节点级配置与定义在本层读，流程级变量/创建输入沿父链上溯，于是同一解析器被多节点复用时各拿各的参数。
- 泳道物化：串行走查到达才建，并行扇出前补齐；按 `(节点, 分片键)` 幂等复用。
- 并发档：泳道串行与并行两档（默认串行），并行扇出到分片专用池，避免与外层节点扇出、内层动作扇出互抢线程。
- 空集合语义：分片键解析出空集合时该节点静默判成功；要表达"没有分片就是失败"必须由业务在解析器里抛异常。
- 作用域即执行范围：分片键集合就是本节点的执行范围；分片只发生在叶子节点，容器节点不得带分片。
- 泳道有独立的 `config` / `result` 桶；泳道结束把结果落回泳道行，供恢复与排障读取。

### 3.5 动作（action）

- 处理器只返回状态：返回终态（通常 `success`）或让渡态；**抛异常 = 失败**；返回空视为成功。
- 结果由处理器自己写进上下文桶，引擎跑完持久化回对应行；引擎不自动把结果挂到任何上层。
- 声明式跳过用 `when` 守卫，不在处理器里做动态跳转。
- 契约是**至少一次**执行，处理器必须幂等；动作行记录被执行的次数（`visit_count`）供幂等与重跑排查。
- 可补偿性由处理器按上下文现判（同一处理器的不同动作可有不同结论）；补偿与重放是两个独立契约。
- 激活期解析后仍解不出的引擎占位符路径必须写进 `result` 的保留键 `__unresolved`，让静默失配变可见。

### 3.6 上下文与数据交接

- 四层上下文：流程 / 节点 / 泳道 / 动作；动作上下文可读所属节点。实例树与上下文父链同形。
- 每层带 `config` / `params` / `result` 三个桶；流程级额外有 `vars`。`vars` 与"当前用户"只存流程级，任意层读写逐级向上委派。
- **桶相互隔离**：引擎不得自动把下层值写进任何上层桶（无结果上挂、无组内冒泡）；跨层共享一律由使用者显式放置——写目标层结果桶、写流程级变量、或写业务专表。
- 两级读法：**本层直取单键**（平铺精确命中，不上溯不上钻）与**沿父链上溯解析**（支持点号下钻）；不提供跨三桶合并的模糊读取。
- 泛型读取：按 key 读取返回调用点推断的类型，类型不符在调用点当场失败，不后漂。
- 流程级变量与流程级结果桶用**脏标记**驱动落库：驱动中随时可刷（动作边界也刷，见 3.6.1）、收尾再刷一次（收尾监听器的写也要落住）；从库重建时不得置脏。
- 回退路径**不刷**流程级结果桶（前置监听器现取的连接信息/凭据只活在内存），但可以刷变量。
- 并发安全：并行子节点/泳道会并发写流程级桶；变量桶必须并发安全，写与快照读必须串行化，落库用快照。
- 流程上下文必须挂载钉死版本的定义，使监听器在前置切点就能读到全量拓扑与节点配置（不必等实例行）。
- 变量桶不接受空值：写了但留空的键视为不存在，显式写空值等于删键。

#### 3.6.1 动作边界：上层结果先行持久化（新增特性）

- **触发点**：动作处理器返回后、动作行状态（成功/失败/跳过/让渡）落库之前。
- **范围**：动作上下文之上的所有层——泳道 `result`、节点 `result`（含聚合节点父链）、流程 `result` 与 `vars`。
- **动机**：动作行一旦落成功/跳过，重入就会跳过该行；若处理器通过 `putResult`/`putVar` 显式放到上层的交接数据尚未落库，崩溃后这部分数据将永久丢失，表现为"动作成功但数据没了"。
- **顺序铁律**：先持久化上层 result（以及流程级 vars/result 脏桶）→ 再更新动作行状态。上层写失败时不得把动作行翻成成功/跳过（会被重入跳过），应保持非终态并让本次驱动失败，重入重跑（至少一次）。
- **幂等**：上层 result 以整桶快照覆盖，重复刷不得产生重复数据或副作用。
- **并发**：并行动作/泳道写同一上层桶时必须串行化（同一锁内判脏、取快照、写库、清脏），不得丢更新。
- **只刷有变化的桶**：以脏标记或快照比较判断，不得每个动作都全量重写所有祖先。
- **段同口径**：动作级 setup/setdown 段与主段适用同一顺序，段动作的写入也必须先落上层、再翻段行状态。
- **范围外**：回退路径不适用（回退不刷流程级 result，现场由回退自己的重建逻辑负责）。
- **落地状态**：当前实现尚未满足该顺序，见 7.2 GAP-01；本条为目标要求。

落库顺序：

```text
handler 返回
  → 刷上层 result / vars（泳道 → 节点 → 流程，只刷有变化的桶）
  → 落动作行状态 + 动作行 result
  → action after 监听器 / 观察者
```

### 3.7 占位符与条件

- 保留作用域：只有以 `vars./params./config./result.` 或 `process./node./lane./action.` 开头的占位符才由引擎解析；其余原样保留。
- 桶级写法本层优先、沿父链上溯；层级锁定写法只读那一层的本桶。
- 两档时机：**物化期**解析（用创建期初始变量；结果桶与配置桶留待运行期）与**激活期**解析（读运行期实时变量与结果）。
- 物化即定型：物化期解得出就烙成字面量（此后变量变化不回溯影响该行），解不出就退化为活引用每次现取。
- 间接键选支：占位符路径里可再嵌占位符（由内向外先插值再取值），用于"按运行期值挑一份片段"；引擎不得内置任何业务保留键名。
- 部分解析固化：指针变量有值但外层取不到值时，回写已插值的路径（指针在解算那一刻固化）。
- 递归有界：取到的值本身是模板时只再填一轮，内层不再插值、不再二次填值，自引用不得递归成环。
- 残留可见：必须能列出"引擎该解却没解出来"的残留路径（只报保留写法），供告警与实例行留痕。
- 条件求值：等于/不等/大小比较、与或非、括号分组、带引号字面量、数值优先否则字符串比较；空表达式判真。
- 求值铁律：条件只能读**已持久化**的桶（保证恢复确定性）；未解析的引擎占位符必须整条判假并告警；外来模板按字面量比较。
- 条件求值实现可整体替换为更强的表达式引擎，接口语义不变。

### 3.8 监听器与观察者

| 能力 | 要求 |
| --- | --- |
| 四类声明式监听器 | 流程级 / 节点级 / 动作级 / 回退级；各自只收本层上下文类型（类型即作用域，编译期不可混用） |
| 两切点 | 每类只有前置与收尾：前置抛异常＝否决（流程失败 / 整节点失败 / 整动作失败 / 整轮回退不执行）；收尾＝纯通知且吞掉异常 |
| 声明顺序 | 监听器声明只有名字与配置两项；执行顺序＝声明顺序，不设排序字段 |
| 全局链 | 全局节点级与全局动作级链声明一次即对所有节点/动作生效；与本地链合并时全局在前、不去重 |
| 来源 | 生效链由钉死版本的定义推导，不落实例快照 |
| 观察者 | 全局自动生效（注册即生效、无需 YAML 声明、无名字与配置、纯观察不可否决），覆盖流程/节点/动作三层前后，异常一律吞掉 |
| 切点次序 | 观察者前置 → 监听器前置 → 实际执行 → 监听器收尾 → 观察者收尾 |
| 注册与路由 | 处理器与四类监听器以 Spring Bean 自动注册、按名字路由；重名注册必须拒；取不到必须明确报错；分片解析器同样按名字路由、重名拒 |

### 3.9 错误策略与收敛

- 两档策略：快速失败（默认）与失败继续。
- 流程级声明一次即对所有未自行声明的节点（含匿名控制节点与其泳道）生效；节点自己声明优先（单值覆盖，不像监听器链那样拼接）。
- 序列收敛就近优先：坏的那一项自己声明过就听它的，没声明才回落本层；**容器内部收敛只看容器那一条**，子项声明不得跨层。
- drain 语义：快速失败不得强行中断已在跑的任务——只取消尚未开始的排队项，等全部结束后聚合失败；串行则停止发起后续项，并把已建未跑的行标为停止。
- 终态聚合：容器/流程按严重程度取最差（`failed > stopped > success/skipped`）；让渡感知时坏终态优先 > 让渡 > 严重程度。
- 取消闸门单点：取消判断只认流程实例状态这一份真值，驱动路径每步当场读库；引擎不得持有本机取消状态或缓存。
- 业务自愿收敛：向长循环业务暴露取消位（动作上下文上置，不查库），由业务自行收敛，框架不强中断。
- 异常统一：业务执行路径的失败必须抛 `ProcessException`，携带消息键与参数；落库摘要必须带键（见 1.5.1）。

### 3.10 干预与恢复

| 干预 | 语义 |
| --- | --- |
| 暂停 | 把执行中的流程置 `paused`：在跑的收敛、未跑的不发 |
| 恢复 | 把 `paused` 翻回 `pending` 重新入队；已完成项重入跳过。处理器让渡到暂停态的流程走同一恢复入口 |
| 停止 | 把执行中或暂停的流程置停止；只翻闸门，不强中断；开了 `settleOnStop` 走两阶段 |
| 整轮重试 | 以流程实例为发起单位：扫完整棵实例树，把"本轮没跑成"的行（失败/停止/卡途中）复位，容器链与闸门随之翻回可认领，重入即从断点续跑 |
| 定点重跑 | 复位单条动作并沿祖先容器链复位、流程重新入队 |
| 人工跳过 | 把卡住或失败的动作置 `skipped` 并让流程继续推进，留跳过原因 |

复位口径：

- 成功与跳过不得复位（既成事实 + 人工干预结论）；闸门不允许重跑的成功/跳过流程必须返回失败，不把跑成功的流程再跑一遍。
- 无事务下的安全顺序：先判资格（翻不动闸门就一行不碰）+ 闸门最后翻；中途异常时流程尚未进入可被捞起的状态；整段必须可重复调用补完。
- 复位状态时不得清掉业务结果桶内容（结果要留给重跑与排障参考），残留痕迹由驱动侧本轮摘。
- 每次干预改过的行必须以操作人作为更新人；回退发起人在回退记录里同样可查。

### 3.11 回退与重放

- **逆序补偿**：对"已成功且声明可补偿"的动作按执行逆序调用补偿逻辑。
- **不可补偿即停**：遇不可补偿的步骤必须停止并留阻塞记录告警，不得跳过它继续拆前面的。
- **补偿失败即停**：补偿自身异常必须记失败并停止，不无限重试、不外抛给调用方。
- **不重复撤销**：已成功补偿过的动作必须跳过（判据是回退历史里最新一条已补偿）；重复撤销通常比漏撤更糟。
- **历史独立留痕**：每个补偿步骤单独一行历史记录（关联原动作），不回写原动作实例的状态（它是不可变的执行事实）；补偿态机：进行中 → 已补偿 / 补偿失败 / 阻塞。
- **现场重建**：补偿路径必须以实例行重建上下文（含分片负载现场重建与激活期占位符解析），使补偿能读到运行期写入的值与回退前置现取的现场信息。
- **回退专用切点**：补偿不走正常驱动路径，因此必须为回退单独提供前置/收尾一对切点：前置可否决整轮，收尾只收聚合结果。
- **凭据不落库**：回退前置挂进流程级结果桶的现场信息必须只活在内存（回退路径不刷该列）。
- **两步入口**：提供"发起回退请求（翻闸门）+ 执行回退（返回报告）"；报告必须能区分已补偿/阻塞/失败/跳过与否决原因，并给出聚合结果。
- **重放闭环**：撤销后再重试，引擎先按执行顺序重放被撤销的副作用（补偿与重放交替留痕），于是"回退 → 重试 → 再回退 → 再重试"可重复闭环。

### 3.12 进度与可观测

- 进度聚合：按流程实例汇总所有已物化动作的状态计数、完成数与百分比（完成＝成功 + 跳过），并给出每个状态计数（含零值项）。
- 明细字段：动作实例键、动作引用键与展示名、状态、分片键、所属节点键与节点展示名、执行段、跳过原因/失败摘要（从结果保留键读）。
- 分组视图：一个命名容器一行（标题 + 自身状态 + 自己的小计与明细）；判据是行上的定义引用键非空，而不是逐个类型硬编码；新增容器形态不得回来加分支。
- 视图直接读列：展示信息直接来自实例行，不回查定义、不解析配置自述键。
- 口径声明：总数/完成数是**已物化部分**的口径（泳道与动作随驱动增长）；校验类流程建议创建期全量物化以稳定节点级分母。
- 执行段口径：统计只算主段行（"一个节点 = 一个校验项"的心智与分母不变）；段行仍进明细并带 `segment` 字段；存量行无段值按 `main` 计。
- 全链路日志：认领、创建、每层否决/异常、收尾终态、回退每步、干预复位数都必须有日志；失败不只躺在日志里，必须同时落库。

### 3.13 对外接口与集成

- **单一门面**：以一个门面提供全部能力（创建、创建并执行、启动、暂停、恢复、停止、重试、定点重跑、跳过、请求回退、执行回退、进度）；业务键一律字符串。
- **创建与执行分离**：支持"只创建不执行"（等调度接手）与"创建并立即执行"，后者可选带路由标签的重载。
- **返回口径**：执行类入口返回"实例 id + 调用结束时的状态（坏终态附一条失败摘要）"；干预类返回是否真的生效（布尔）；回退返回报告；查询返回结构。
- **不暴露持久化行**：对外返回不得是持久化实体行；物理主键不外露，裸 JSON 不让调用方自解析，可变对象不外抛。
- **流式语法糖**：可选链式构建入口（版本、创建人、路由、参数逐段填充，末尾只创建或创建并执行），且不新增任何引擎语义：空参数等价传空、键名不做点号展开、一次性非线程安全。
- **REST 入口**：可选提供创建（可选自动启动）、启动、暂停、恢复、停止、回退、重试（流程级与动作级）、跳过、进度；操作人缺省为系统；未引入 web 框架的宿主不得因装配失败。
- **会话自理**：引擎不管用户会话；创建人由调用方取好传入，操作人显式传入；无线程本地上下文。
- **装配**：必须以单个配置类作为集成点，宿主一行导入即完成装配；引擎自建专用持久化设施（独立 Bean 名 + 独立包名），与宿主 MyBatis 双向不干扰；数据源只取宿主提供的（恰好一个或有主 Bean 时自动取用，无法判定时允许显式指定，引擎不得创建默认数据源）。
- **并发池**：节点扇出、分片扇出、动作扇出各一个独立线程池 Bean，参数可独立配置、同名 Bean 可被宿主覆盖；池满时由提交方线程自跑（背压），不得出现 owner 线程 hold 等待子任务造成假死。
- **业务键序列**：五类业务键各绑定宿主一个序列号生成器 Bean（按名字匹配）；缺 Bean 不得启动失败，但取号时不得回落本地自造号——取不到号源必须当场报错并说清缺哪个名字。
- **异常文案**：文案由引擎自带的 classpath 资源提供（不声明 Bean、不经容器），宿主可整体替换；取文案本身绝不允许抛异常。

### 4.3 流程（PRC）

| 编号 | 需求 |
| --- | --- |
| PRC-01 | 创建必须落 `pending` 并返回流程实例业务键；创建参数进流程级配置桶；创建人可选 |
| PRC-02 | 创建必须支持"只创建"与"创建并立即执行"两类入口；执行入口可带可选路由标签 |
| PRC-03 | 启动必须以比较交换取得唯一驱动权；抢不到不得抛异常，只回报当下状态 |
| PRC-04 | 一个流程必须由单个 owner 递归驱动整棵树；流程内并发由 owner 的池铺开 |
| PRC-05 | 顶层必须按"前置 → 主流程 → 收尾"驱动；收尾具备 finally 语义，其结果参与终态聚合；让渡轮除外 |
| PRC-06 | 已落终态的节点行/动作行在重入时必须直接跳过；非终态行必须重跑；缺行必须补齐；不得引入第二套恢复语义 |
| PRC-07 | 流程终态必须按严重程度取最差（失败 > 停止 > 成功/跳过）；让渡必须按"坏终态 > 让渡 > 严重程度"聚合 |
| PRC-08 | 处理器返回让渡态时本轮必须立即退出：收尾段与后续根不跑、剩余项不 drain、容器不落终态；重入按至少一次重跑 |
| PRC-09 | 非法驱动返回值（非终态且非让渡）必须归一为失败，不得静默过聚合 |
| PRC-10 | 停止必须支持硬停与"先收尾"两档；先收尾策略必须在创建期钉死，停止与驱动只读流程行 |
| PRC-11 | 自动回退必须在失败/停止终态收尾后逆序补偿；暂停不得触发；回退异常不得改写调用方拿到的终态 |
| PRC-12 | 回退过的流程在重新驱动前必须按执行顺序正序重放被撤销的副作用；重放失败必须落失败挂起、不得向前驱动、不得触发自动回退 |
| PRC-13 | 流程失败摘要必须只记本次驱动首条；坏终态才落库，好终态必须摘除残留；未铺开就失败的路径也必须兜底落终态 |
| PRC-14 | 调度能力必须支持限量认领、批量捞取、异步驱动、按路由维度过滤、可禁用；未路由流程不得被主动认领 |
| PRC-15 | 调度器不得默认强制装配；未装配时必须仍可同步触发执行 |
| PRC-16 | 单 owner 模型下必须允许人工重试接管崩溃遗留的僵持流程；不得声称具备自动接管能力 |

### 4.4 节点（NOD）

| 编号 | 需求 |
| --- | --- |
| NOD-01 | 节点类型必须覆盖动作、并行、条件、聚合；循环类型只能作为预留，不得提供半成品实现 |
| NOD-02 | 单处理器节点必须等价于"一条动作"，使行与动作定义的下标对齐路径只有一条 |
| NOD-03 | 并行容器必须支持匿名与命名两种形态；命名容器必须能携带自己的策略、守卫、配置、节点级监听器 |
| NOD-04 | 并行扇出必须 join 聚合；快速失败只取消未开始项，已在跑的必须让其跑完 |
| NOD-05 | 条件节点必须支持 then 与可选 else；选中支必须持久化并在恢复时复用；未选支不得驱动但必须留可诊断的已跳过行；无分支可走判跳过 |
| NOD-06 | 聚合节点必须为命名串行容器；组级守卫、策略、配置、监听器、段必须生效；组内共享必须由使用者显式放置，引擎不得自动冒泡 |
| NOD-07 | 一种节点类型的"建行"与"驱动"必须归在同一份类型档案中；新增类型不得修改既有分发逻辑 |
| NOD-08 | 节点行必须在物化期冻结：生效错误策略、守卫、业务配置、定义引用键与展示名快照 |
| NOD-09 | 实例行必须与定义表达式按声明顺序对齐；已存在行复用、缺行补建、不得路径反查 |
| NOD-10 | 半物化状态必须可愈合：重新驱动补齐缺行、不重复建、不改已有拓扑顺序 |
| NOD-11 | 节点执行顺序必须按 flow 前序展开，不得使用节点表书写顺序 |

### 4.5 泳道（LAN）

| 编号 | 需求 |
| --- | --- |
| LAN-01 | 节点声明分片解析器即成为分片节点；一个分片键必须对应一条泳道 |
| LAN-02 | 分片必须分两阶段：先解析全部分片键（幂等稳定），再按分片键现场重建强类型负载（不落库） |
| LAN-03 | 分片解析必须以节点上下文为入参，使同一解析器被多节点复用时各拿各的参数 |
| LAN-04 | 泳道必须在走查到达时创建或扇出前补齐，并按 `(节点, 分片键)` 幂等复用 |
| LAN-05 | 泳道必须支持串行与并行两档；并行必须使用分片专用并发池 |
| LAN-06 | 分片键为空集合时该节点必须静默判成功；业务要表达失败必须自行抛异常 |
| LAN-07 | 分片只能发生在叶子节点；容器节点不得声明分片 |
| LAN-08 | 泳道必须拥有独立的配置桶与结果桶，结果必须随泳道结束落库 |
| LAN-09 | 分片节点默认必须"每泳道一套三段回路"；声明段不跟随分片时，节点级段整节点各一次、动作级段仍逐泳道 |

### 4.6 动作（ACT）

| 编号 | 需求 |
| --- | --- |
| ACT-01 | 动作处理器必须只返回状态，不返回结果对象或跳转指令；抛异常即失败，返回空视为成功 |
| ACT-02 | 动作结果必须由处理器显式写进上下文桶，引擎不得自动上挂到任何上层 |
| ACT-03 | 条件跳过必须使用声明式守卫，不得由处理器在内部做动态跳转 |
| ACT-04 | 动作执行必须至少一次，处理器必须幂等；动作行必须记录执行次数 |
| ACT-05 | 动作必须支持成对的补偿与重放契约；可补偿性必须能按动作上下文现判 |
| ACT-06 | 激活期仍解不出的占位符路径必须写入未解析清单保留键 |
| ACT-07 | 动作行必须按 `(节点, 动作定义键, 分片键, 段)` 唯一定位；段行与主段行同生命周期 |
| ACT-08 | 动作行状态更新必须排在上层 result 持久化之后；动作级段同口径；上层写失败不得把动作行翻成成功/跳过/让渡态 |

### 4.7 段（SEG）

| 编号 | 需求 |
| --- | --- |
| SEG-01 | 流程级必须支持前置/主流程/收尾三段；收尾必须 finally 执行 |
| SEG-02 | 叶子节点必须支持内联的前置/主体/收尾三段；段不进 flow DSL |
| SEG-03 | 聚合节点必须支持组级段包住整个子节点序列；段可写组声明内或节点同级，两处等价、同字段两处都写必须拒 |
| SEG-04 | 动作级段必须成对声明；段动作不得再挂段（深度锁 1）；声明动作级段的节点不得开启动作并行 |
| SEG-05 | 前置段失败必须跳过主体，收尾段必须照跑；收尾段内不收敛 |
| SEG-06 | 段重入必须幂等：已成功段跳过；现场被收尾撤除后必须按成对重臂补跑；`repeatSegments` 可显式改为每趟重跑 |
| SEG-07 | 段行必须带 `segment` 值；存量行按主段计；统计与回退只扫主段，段行仅进明细 |
| SEG-08 | 段与开关的死配置、非法声明值必须在装载期拒绝 |

### 4.8 上下文与交接（CTX）

| 编号 | 需求 |
| --- | --- |
| CTX-01 | 必须提供流程/节点/泳道/动作四层上下文，实例树与上下文父链必须同形 |
| CTX-02 | 每层必须有 `config`/`params`/`result` 三桶；流程级额外有 `vars`；`vars` 与当前用户只存流程级 |
| CTX-03 | 各层桶必须相互隔离；引擎不得自动把下层值写进上层桶 |
| CTX-04 | 必须区分本层直取（平铺、不上溯）与沿父链上溯解析（支持点号下钻）；不得提供跨三桶合并读取 |
| CTX-05 | 按 key 读取必须返回调用点推断的类型，类型不符必须在调用点失败 |
| CTX-06 | 跨层交接必须由使用者显式写入目标层；引擎零自动上写 |
| CTX-07 | 流程级变量与结果桶必须脏标记驱动落库；驱动中可刷（含动作边界）、收尾再刷；从库重建不得置脏 |
| CTX-08 | 回退路径不得刷流程级结果桶，但可以刷变量 |
| CTX-09 | 变量桶必须并发安全；写与快照读必须串行化，落库用快照 |
| CTX-10 | 流程上下文必须挂载钉死版本定义，使前置监听器可读到全量拓扑 |
| CTX-11 | 变量桶不得接受空值；显式写空等于删键 |
| CTX-12 | 动作结束后、动作行状态变更前，必须先把动作显式写入的上层 result（泳道/节点/流程）与流程 vars 持久化；上层写失败时动作行不得翻成成功/跳过/让渡态，重入重跑 |
| CTX-13 | 上层 result 的重复刷写必须幂等（整桶快照覆盖）；并行动作写同一上层桶必须串行化，不得丢更新 |
| CTX-14 | 上层 result 只刷有变化的桶（脏标记或快照比较），不得每个动作全量重写所有祖先 |

### 4.9 占位符与条件（VAR）

| 编号 | 需求 |
| --- | --- |
| VAR-01 | 只有以保留桶前缀或层级锁定前缀开头的占位符才由引擎解析，其余原样保留 |
| VAR-02 | 必须支持两档解析：物化期（初始变量）与激活期（运行期变量/结果） |
| VAR-03 | 物化期解出即烙字面量；解不出退化为活引用每次现取 |
| VAR-04 | 必须支持路径内嵌占位符（间接键），由内向外先插值再取值；引擎不得内置业务保留键 |
| VAR-05 | 指针有值但外层取不到时必须回写已插值路径，不再依赖指针后续变化 |
| VAR-06 | 递归有界：取到的值本身是模板只再填一轮，内层不再插值、不得成环 |
| VAR-07 | 必须能列出该解而未解出的保留路径，供告警与实例行留痕 |
| VAR-08 | 条件求值必须支持等于/不等/大小比较、与或非、括号、引号字面量、数值优先否则字符串比较；空表达式判真 |
| VAR-09 | 条件只能读已持久化桶；未解析的引擎占位符必须整条判假；外来模板按字面量比较 |
| VAR-10 | 条件求值实现必须可整体替换，接口语义不变 |

### 4.10 策略与收敛（POL）

| 编号 | 需求 |
| --- | --- |
| POL-01 | 必须支持快速失败与失败继续两档，默认快速失败 |
| POL-02 | 流程级策略必须对所有未自行声明的节点（含匿名控制节点与泳道）生效 |
| POL-03 | 节点自己的声明必须优先于全局；单值语义为覆盖而非拼接 |
| POL-04 | 根序列收敛必须就近声明优先；容器内部收敛只能看容器自己那一条，子项声明不得跨层 |
| POL-05 | drain 必须只取消未开始项，不得强行中断已在跑的任务 |
| POL-06 | 终态聚合必须按严重程度取最差，并保持让渡感知 |
| POL-07 | 取消判断必须只认流程实例状态这一份真值，每步当场读库 |
| POL-08 | 必须向长循环业务暴露取消位，由业务自行收敛，框架不强中断 |

### 4.11 监听与观察（OBS）

| 编号 | 需求 |
| --- | --- |
| OBS-01 | 必须支持流程级、节点级、动作级、回退级四类声明式监听器，各自只收本层上下文 |
| OBS-02 | 每类监听器只有前置与收尾两个切点；前置抛异常可否决；收尾纯通知且吞异常 |
| OBS-03 | 监听器执行顺序必须等于声明顺序；不得引入排序字段 |
| OBS-04 | 必须支持全局节点级/动作级链，与本地链合并时全局在前、不去重 |
| OBS-05 | 生效链必须由钉死版本定义推导，不落实例快照 |
| OBS-06 | 必须支持注册即生效的观察者，覆盖流程/节点/动作三层前后，纯观察不可否决且吞异常 |
| OBS-07 | 切点次序必须固定：观察者前置 → 监听器前置 → 实际执行 → 监听器收尾 → 观察者收尾 |
| OBS-08 | 处理器、监听器、分片解析器必须按名字路由；重名注册必须拒；取不到必须明确报错 |
| OBS-09 | 回退路径不得触发正常驱动的三类监听器与段，必须使用回退专用切点 |

### 4.12 干预（INT）

| 编号 | 需求 |
| --- | --- |
| INT-01 | 必须支持暂停与恢复；恢复必须重新入队，已完成项重入跳过 |
| INT-02 | 必须支持停止；只翻闸门，不强中断；终态上必须返回失败 |
| INT-03 | 必须支持以流程实例为单位的整轮重试：复位本轮未跑成行、复位容器链与闸门 |
| INT-04 | 成功与跳过不得复位；不可重跑的成功/跳过流程必须返回失败 |
| INT-05 | 干预写库必须"先判资格 + 闸门最后翻"，中途异常不得让流程进入可被捞起状态；整段必须可重复调用 |
| INT-06 | 必须支持按单条动作定点重跑，并沿祖先容器链复位 |
| INT-07 | 必须支持人工跳过动作并留跳过原因 |
| INT-08 | 复位状态不得清空业务结果桶 |
| INT-09 | 每次干预改过的行必须以操作人作为更新人 |

### 4.13 回退与重放（RBK）

| 编号 | 需求 |
| --- | --- |
| RBK-01 | 必须对已成功且可补偿的动作按执行逆序补偿 |
| RBK-02 | 遇不可补偿步骤必须停止并留阻塞记录，不得跳过继续 |
| RBK-03 | 补偿自身异常必须记失败并停止，不得无限重试或外抛 |
| RBK-04 | 已成功补偿的动作不得重复撤销；判据必须是回退历史最新一条已补偿 |
| RBK-05 | 每个补偿步骤必须单独留痕并关联原动作；不得回写原动作行状态 |
| RBK-06 | 补偿路径必须从实例行重建上下文，含分片负载现场与激活期占位符解析 |
| RBK-07 | 回退必须有独立的前置/收尾切点；前置可否决整轮 |
| RBK-08 | 回退前置挂进流程级结果桶的现场信息不得落库 |
| RBK-09 | 必须提供"发起回退请求 + 执行回退"两步入口，报告必须区分已补偿/阻塞/失败/跳过与否决原因 |
| RBK-10 | 回退后重试必须先按执行顺序重放；重放失败不得向前驱动且不得自动回退；补偿与重放必须交替留痕以支持重复闭环 |

### 4.14 进度与可观测（MON）

| 编号 | 需求 |
| --- | --- |
| MON-01 | 必须按流程实例汇总已物化动作的状态计数、完成数与百分比；完成＝成功 + 跳过 |
| MON-02 | 明细必须带动作实例键、动作引用键与展示名、状态、分片键、所属节点键与展示名、执行段、跳过原因/失败摘要 |
| MON-03 | 必须提供"一个命名容器一行"的分组视图；判据是行上定义引用键非空，不得按类型硬编码 |
| MON-04 | 展示信息必须直接读实例行列，不回查定义、不解析配置自述键 |
| MON-05 | 必须明确总数/完成数是已物化部分的口径，并说明稳定分母的做法 |
| MON-06 | 认领、创建、每层否决/异常、收尾终态、回退每步、干预复位数必须有日志；失败必须同时落库 |

### 4.15 接口与装配（API）

| 编号 | 需求 |
| --- | --- |
| API-01 | 必须以单一门面提供创建、执行、干预、进度、回退的全部组合能力 |
| API-02 | 执行类入口必须返回实例 id + 调用结束时状态；坏终态附一条失败摘要；不得承诺终态、不得造假状态 |
| API-03 | 对外返回不得是持久化实体行；物理主键不得外露 |
| API-04 | 可提供链式语法糖，但不得新增引擎语义；空参数等价传空、键名不做点号展开、一次性非线程安全 |
| API-05 | 干预入口必须返回是否真的生效；回退必须返回报告；查询必须返回结构 |
| API-06 | 可选提供 REST 入口；未引入 web 框架的宿主不得因装配失败 |
| API-07 | 引擎不得管理用户会话；创建人与操作人必须由调用方显式传入 |
| API-08 | 必须支持单配置类装配；持久化设施必须与宿主隔离；数据源只取宿主提供的；不得创建默认数据源 |
| API-09 | 必须提供三档独立并发池，池满必须背压（提交方线程自跑），不得造成 join 饥饿 |
| API-10 | 五类业务键必须支持宿主序列号生成器接入；缺 Bean 不得启动失败，但取号不得本地自造 |
| API-11 | 异常文案必须由引擎自带资源提供、可整体替换；取文案本身不得抛异常 |
| API-12 | 新增返回类型与语法糖不得改变既有方法签名与行为 |

### 4.16 非功能（NFR）

| 编号 | 需求 |
| --- | --- |
| NFR-01 | 运行时依赖必须限于 Spring 容器与 JDBC、MyBatis、YAML 解析、JSON、SLF4J 门面；web 与数据库驱动可选 |
| NFR-02 | 第三方库版本必须是契约下界，写法必须兼容一个版本区间 |
| NFR-03 | 必须假定多节点部署，所有闸门与状态判断当场读库 |
| NFR-04 | 任意时刻崩溃后重新驱动必须走同一套重入路径（终态跳过、缺行补齐、闸门以库为准） |
| NFR-05 | 必须能解析并缓存远超常规大小的定义文本 |
| NFR-06 | 单元与端到端测试必须不起容器；mapper 语句级回归必须使用替身 JDBC，不依赖内存库 |
| NFR-07 | 覆盖率工具必须以独立构建剖面启用，默认构建行为不变 |
| NFR-08 | 构件必须附带源码包，便于宿主排障 |
| NFR-09 | 必须支持表前缀整体替换，8 张表一律派生，不得有固定名特权 |
| NFR-10 | 必须支持"宿主一个 SPI 都没实现"的零实现装配；所有注册表必须容忍零候选 |

### 4.17 硬性约束（HC）

| 编号 | 需求 |
| --- | --- |
| HC-01 | 引擎侧业务执行失败必须统一抛 `ProcessException`，携带消息键与可变参数；装配/编程期参数校验可用 `IllegalArgumentException`，但不得进入运行期失败摘要 |
| HC-02 | `ProcessException` 只保留两个构造签名（带/不带 cause）；宿主同名类对齐这两个构造即可替换 |
| HC-03 | 消息键必须落在 `AU204001`~`AU204999`，按功能域分段，一键一文案，参数按位置填充 |
| HC-04 | `toString()` 必须带键（`类名[键]: 文案`），`getMessageKey()`/`getArgs()` 必须可用 |
| HC-05 | 文案默认由引擎自带 classpath bundle 提供，可整体替换；取文案过程绝不允许抛异常 |
| HC-06 | 文案不得含单引号（MessageFormat 转义）；新增文案必须按 UTF-8 写入 |
| HC-07 | 业务键必须由 `com.tt.bb.sequence.StringSequenceGenerator` 生成，接口方法为无参 `String getStringSequence()` |
| HC-08 | 五类业务键必须按固定 Bean 名绑定（processInstSequenceGenerator / nodeInstSequenceGenerator / laneSequenceGenerator / actionInstSequenceGenerator / rollbackRecordSequenceGenerator），不得串号 |
| HC-09 | 序列 Bean 注入必须可选；取号缺失必须抛 `AU204801` 并报出缺失的 Bean 名；不得本地自造号 |
| HC-10 | 业务键列宽 `VARCHAR(32)`；唯一性由宿主序列负责，引擎不去重、不改写号源格式 |

## 5 状态与判定口径

### 5.1 运行态

| 状态 | 含义 | 终态 | 严重度 | 备注 |
| --- | --- | --- | --- | --- |
| `created` | 已计划、占位、不可认领 | 否 | 0 | 预插入行 |
| `pending` | 已激活、等调度认领 | 否 | 0 | 也可作让渡态（由调度重捞） |
| `running` | 执行中 | 否 | 0 | 有 owner |
| `success` | 成功 | 是 | 1 | 完成且不拦后续 |
| `skipped` | 跳过 | 是 | 1 | 对控制流等价成功 |
| `failed` | 失败 | 是 | 3 | 最坏 |
| `stopped` | 停止 | 是 | 2 | 人工停或 drain 后 |
| `paused` | 暂停 / 让渡 | 否 | 0 | 人工可恢复 |
| `suspended` | 系统挂起 / 让渡 | 否 | 0 | 本期无唤醒入口 |

### 5.2 聚合与让渡

- 普通聚合：`failed > stopped > success/skipped`；`skipped` 与 `success` 都算完成。
- 让渡感知聚合：先归一非法非终态为 `failed`；坏终态优先 > 让渡 > 严重度聚合。
- 让渡合法值只有 `pending/paused/suspended`；`created`/`running` 不是合法返回值。
- 动作边界的落库顺序独立于聚合口径：上层 result 必须先于动作行状态落库（见 3.6.1）。

### 5.3 补偿 / 重放态

```text
补偿：compensating -> compensated / compensate_failed / blocked
重放：restoring    -> restored / restore_failed
```

- 某动作当前处于哪一步，只看它**最新一条**回退记录：最新是 `compensated`（或重放中途的 `restoring/restore_failed`）= 还欠一次重放；最新是 `restored` = 现场已恢复。
- 补偿与重放交替留痕，原动作行始终不变，因此"回退 → 重试 → 再回退 → 再重试"可重复闭环。

### 5.4 发布态

`draft`（草稿，只能按版本精确定位）→ `published`（发布，取最新版本命中）→ `archived`（归档，不再参与最新版本认领）。

## 6 端到端串讲（层级如何落到一次执行）

以"数据库迁移"为例：

```text
setup:  initTopology
flow:   fetchTopology, preCheck, PARALLEL(migrateData, buildIndex), postCheck,
        IF(${vars.dialect}=='goldendb', gdbVerify, mysqlVerify)
setdown: finalizeReport
```

一次执行依次穿过各层：

1. **定义**：解析 YAML，得到流程级三段、节点表、flow 表达式树；装载期拒绝非法命名与段声明。
2. **流程实例**：创建落 `pending`，钉死版本；启动认领翻 `running`。
3. **前置**：`initTopology` 作为顶层根驱动；其节点行、动作行按需物化。
4. **节点**：`preCheck` 为分片叶子，按拓扑解析出 N 个分片键 → N 条泳道；默认每泳道一套 `setup → main → setdown`。
5. **泳道**：各泳道按串行/并行档执行；泳道内动作按 `actionExecution` 档执行；每个动作按"观察者前置 → 监听器前置 → 处理器 → 上层 result 先行落库 → 动作行落状态 → 监听器收尾 → 观察者收尾"的目标顺序执行（上层结果先行见 3.6.1）。
6. **并行容器**：`PARALLEL(migrateData, buildIndex)` 扇出，join 聚合；快速失败时只取消未开始项，等待在跑项结束。
7. **条件容器**：`IF` 读取已持久化变量判定方言，决策落 `__chosen`，只驱动选中支；未选支留一行 `skipped` 痕迹。
8. **收尾**：`finalizeReport` 无论如何都执行；其结果参与流程终态聚合。
9. **异常路径**：失败 → 流程行记首条 `__error`；若开自动回退则逆序补偿；人工修好现场后重试，引擎先正序重放被撤销的副作用，再从断点续跑。
10. **观测**：进度接口按动作行汇总，段行只进明细；命名容器各占一行，便于前端按校验项展示。
