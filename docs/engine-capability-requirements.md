# 通用逻辑编排引擎 能力需求清单（指导设计与代码生成）

| 项 | 内容 |
| --- | --- |
| 文档版本 | v1.0（由当前实现逆向提炼，能力粒度） |
| 适用工程 | `orchestrator-engine`（Java 8 可嵌入组件库） |
| 文档用途 | **能力全景清单**：设计时按域拆分职责，代码生成时按编号逐条落地，评审时按编号核对是否漏能力 |
| 抽象层级 | 只回答"引擎必须提供什么能力、口径是什么"，**不**规定类名/方法签名/SQL 写法/文件布局 |
| 配套文档 | 逐字刚性契约与实现细节见 [`engine-requirements.md`](./engine-requirements.md)；本文与它冲突时以本文 **GAP** 一节的判定为准 |
| 编号约定 | `CAP-<域>-<序>` 能力项；`OUT-*` 范围外与预留；`GAP-*` 现状与承诺不一致，生成时**必须二选一显式处置** |

**措辞**：`必须`＝刚性，做不到即缺陷；`应当`＝默认做法，偏离需给理由；`可`＝扩展位。

## 1 产品定位

- **嵌入式组件库**（打成 jar 被宿主 Spring 容器引用），不是独立服务、不是 Spring Boot Starter、不自带装配描述符。
- 解决的问题：**多个业务步骤按声明顺序 / 并行 / 条件分支 / 分片展开执行，且要求可观测、可人工干预、可业务补偿、可崩溃后续跑。**
- 两条设计基线（所有能力都围绕它们展开，生成代码时不得违背）：
  - **DB 是真值**：状态、闸门、进度、交接数据一律落库；内存只承载单次驱动的执行栈，任何本机状态都不得成为判断依据。
  - **声明式编排**：业务方只写 YAML 定义 + 实现 SPI，编排语义（顺序/并发/失败收敛/重试/回退）全部由引擎承担。

### 1.1 角色与入口

| 角色 | 关注 | 使用的能力域 |
| --- | --- | --- |
| 流程作者 | 写定义：形状、策略、guard、数据交接 | DEF / CHK / POL / SHD / VAR |
| 业务开发 | 实现 handler、分片解析器、监听器、观察者 | OBS / CTX / VAR |
| 调用方系统 | 创建、启动、查进度、干预、回退 | API / INT / RBK / MON |
| 运维 | 暂停 / 恢复 / 停止 / 重试 / 跳过 / 回退 | INT / RBK |
| 宿主平台 | 数据源、业务键序列、表命名空间、线程池、调度器注册 | DEP / DATA / NFR |

### 1.2 典型场景（能力组合，非需求枚举）

- **全自动迁移**：前置 → 主流程（含并行与条件分支）→ 收尾（无论成败都跑），一次同步调用拿到终态。
- **批量校验**：创建期就把整棵节点树入库（进度分母稳定）+ 全局"失败不拦后续" + 一个校验项 = 一个聚合节点 + 前端轮询分组进度 + 用监听器读写业务专表。
- **失败人工处置**：现场修好后整轮重试（从断点续跑）；或逆序撤销已发生的副作用；定义开了自动回退则失败/停止当场补一轮。
- **多机部署**：创建时给路由标签，只有能力命中的 worker 主动认领它。

## 2 概念模型（必须先立住的结构）

```
流程定义（YAML，不可变，按 (定义标识, 版本) 定位）
   └── 流程实例（一次执行，钉死定义版本）
         └── 节点实例（树：ACTION / PARALLEL / IF / GROUP，parent_id 为空即顶层根）
               ├── 节点实例（容器子节点，可再嵌套）
               └── 泳道 lane（分片节点的一个分片键 = 一条 lane）
                     └── action 实例（最小执行单元，绑定一个 handler）
```

| 编号 | 模型要求 |
| --- | --- |
| CAP-MDL-01 | **实例树与上下文父链必须同形**：容器节点的子上下文挂在容器的节点上下文上，而不是直接挂流程；因此"取流程级"必须沿父链上溯 |
| CAP-MDL-02 | 五层上下文（流程 / 节点 / 泳道 / 动作 + 动作可读的所属节点）各带 `config`/`params`/`result` 三桶，流程级额外有 `vars` |
| CAP-MDL-03 | **各层桶相互隔离**：引擎不得自动把下层值写进任何上层桶（无结果上挂、无组内冒泡）；跨层共享一律由使用者显式放置或写业务专表 |
| CAP-MDL-04 | `vars` 与"当前用户"只存流程级，任意层的读写必须逐级向上委派 |
| CAP-MDL-05 | 节点上下文必须自带实例行：行内字段（类型/策略/分片器/config）与派生信息（定义、展示名）同源，禁止另传一套节点参数形成第二真相 |

## 4 DEP 装配与集成

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-DEP-01 | 统一装配入口 | 引擎必须以**单个 Java 配置类**作为集成点，宿主一行 `@Import` 即完成装配；配置类必须扫描引擎自身的 core / api / util 包 |
| CAP-DEP-02 | 持久化设施隔离 | 引擎必须自建专用 `SqlSessionFactory` 与 mapper 扫描器（独立 Bean 名 + 独立包名），与宿主自己的 MyBatis 设施双向不干扰；SQL 一律集中在引擎自带的 mapper XML |
| CAP-DEP-03 | 表命名空间 | 全部表必须可由整体前缀改名（默认前缀可置空回退裸名），不允许任何一张表享有"固定名特权"；前缀口径必须由单一处派生并被测试共用 |
| CAP-DEP-04 | 数据源取用 | 引擎必须只依赖宿主提供的数据源：上下文恰好一个或有主 Bean 时自动取用，无法判定时允许显式指定；引擎不得创建默认数据源 |
| CAP-DEP-05 | 不托管事务 | 引擎必须不使用事务注解、不要求宿主提供事务管理器；跨语句的一致性靠"先判资格 + 关键写最后 + 全程可重复调用"实现 |
| CAP-DEP-06 | Web 入口可选 | REST 入口必须放在组件扫描范围之外，且 web 依赖声明为可选：未引入 web 框架的宿主不得因装配而失败 |
| CAP-DEP-07 | 三档并发池 | 必须为节点扇出、分片扇出、动作扇出各提供一个线程池 Bean（三池分离避免相互抢占造成假死），池参数可独立配置、同名 Bean 可被宿主覆盖 |
| CAP-DEP-08 | 业务键序列接入 | 五类业务键各绑定宿主一个序列号生成器 Bean（按 Bean 名匹配）；缺 Bean **不得**起不来（启动期不校验），但也**不得**回落本地自造号——取不到号源就当场报错并说清缺哪个名字 |
| CAP-DEP-09 | 异常文案可替换 | 文案必须由引擎自带的 classpath 资源提供（不声明 Bean、不经容器），宿主可整体替换文案来源；取文案这件事本身绝不允许抛异常 |
| CAP-DEP-10 | 配置值注入 | 装配参数必须支持属性注入与非 Spring 直接构造两条路径（便于单测与手工装配） |
| CAP-DEP-11 | 零实现可装配 | 宿主一个 SPI 都没实现时（例如只用引擎跑流程、暂不加监听器与观察者），容器必须照样能起来：所有注册表的集合依赖必须容忍零候选 |

## 5 DEF 定义与 DSL

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-DEF-01 | 定义载体 | 必须支持从 YAML/JSON 文本解析出完整定义对象图；解析必须走安全构造器（禁止任意对象实例化），且必须能容纳大容量定义 |
| CAP-DEF-02 | 流程级声明段 | 必须支持：物化时机、流程级变量初值 `vars`、执行顺序 `flow`、前置 `setup`、收尾 `setdown`、四类监听器链、全局错误策略、自动回退开关、节点表 `nodes`；所有段都可省略，"写了但留空"必须与"整段缺失"同口径 |
| CAP-DEF-03 | 节点声明 | 节点必须支持：展示名、单 handler 或节点内多 action 序列、分片器、lane 串/并行、action 串/并行、节点级 guard、就近错误策略、业务 config、节点级监听器、聚合节点子结构 |
| CAP-DEF-04 | 动作声明 | 动作必须支持：声明 id、展示名、handler、guard、业务 config、动作级监听器 |
| CAP-DEF-05 | 展示名与引用键分离 | 定义 id 是 flow 里的引用键，展示名只用于视图与日志；改展示名不得动 flow |
| CAP-DEF-06 | 单 handler 节点归一 | 只写 handler 的节点必须等价于"一条 action"，使行与动作定义的下标对齐路径只有一条 |
| CAP-DEF-07 | flow DSL 形状 | 必须支持：顶层逗号扁平为多个根（不包虚拟串行根）、`PARALLEL(...)` 并行扇出、`IF(条件, then[, else])` 条件分支、`GROUP:名(...)` 命名串行容器、`PARALLEL:名(...)` 命名并行容器、裸 token 作为节点引用 |
| CAP-DEF-08 | 命名写在关键字后 | 容器命名必须写在关键字与括号之间（括号里只剩形状）；不支持命名的控制结构必须明确拒绝而不是静默退化 |
| CAP-DEF-09 | 语法往返互逆 | flow 文本必须可解析成表达式树，且表达式树必须能写回等价文本（装载期展开聚合节点后需要重写文本，不能往返的语法扩展禁止合入） |
| CAP-DEF-10 | 聚合节点 | 必须支持"一个业务项 = 一个对外名字"的命名串行容器：装载期把组内子节点提升进顶层节点表并重写 flow；组可嵌套，深度有上限 |
| CAP-DEF-11 | 命名并行容器 | 带命名后缀的并行必须能像聚合节点一样就近携带：错误策略、guard、config、节点级监听器 |
| CAP-DEF-12 | 按执行序枚举节点 | 必须能提供"按 flow 执行顺序（前置 + 主流程 + 收尾，容器在前子节点紧随）展开的节点清单"，供进度骨架与开跑前自检使用；不得把节点表的书写顺序当执行顺序 |

## 6 CHK 装载期校验（宁拒不猜）

| 编号 | 校验能力 | 要求 |
| --- | --- | --- |
| CAP-CHK-01 | DSL 语法错误定位 | 多余字符、缺括号、缺节点引用、非法位置等必须当场拒并带位置信息 |
| CAP-CHK-02 | 保留字符 | 冒号只允许作为命名后缀；节点引用里出现冒号必须拒（避免旧写法被静默读成节点名） |
| CAP-CHK-03 | 命名容器空子项 | 命名并行与聚合节点无子项时必须拒 |
| CAP-CHK-04 | 命名与声明成对 | 并行命名后缀必须在节点表有对应声明；声明了容器属性却未被任何 flow 引用（死配置）必须拒 |
| CAP-CHK-05 | 纯容器约束 | 命名容器不得同时声明 handler / actions / shard / lane 或 action 执行方式 |
| CAP-CHK-06 | 聚合节点结构 | 必须有组内 flow 与组内 nodes；子节点键不得与既有键冲突；不得跨组引用另一个顶层聚合节点；嵌套深度有上限 |
| CAP-CHK-07 | 段约束 | 前置/收尾段只接受叶子节点引用，放容器必须拒 |
| CAP-CHK-08 | 枚举与开关声明值 | 物化时机、错误策略、布尔开关的非法声明值必须拒（开关只认真假文本），合法值一律归一化后入库 |
| CAP-CHK-09 | 早失败优先原则 | 一切"用户手写的名字/开关"配错都必须装载期拒；一切运行期才能判定的语义（如 flow 引用未定义节点）允许延迟到驱动期，但必须落到实例行的失败摘要 |

## 7 DCL 定义定位与缓存

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-DCL-01 | 版本定位 | 创建实例时可只给定义标识（取最新已发布版），也可精确指定版本；两者都取不到必须明确报错 |
| CAP-DCL-02 | 版本钉死 | 流程实例必须记录所用定义版本，此后所有驱动/重试/回退都用这一版；定义不可变 |
| CAP-DCL-03 | 解析一次 | 同一 (定义标识, 版本) 的 YAML 必须只解析一次，缓存其规范化快照 |
| CAP-DCL-04 | 借出私有副本 | 每次取定义必须返回一份全新副本（业务代码改它不得污染缓存）；新增定义字段时副本机制必须自动带上（走整体序列化而非手写拷贝） |
| CAP-DCL-05 | 一次驱动只取一次 | 同一次驱动内必须只借一份定义，避免同一次执行出现两个互不相干的定义对象 |
| CAP-DCL-06 | 已知代价透明 | 必须文档化快照往返带来的标量类型漂移与调用纪律（值类型限定在字符串/数字/布尔/列表/映射） |

## 8 DATA 数据模型与持久化

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-DATA-01 | 表集合 | 必须有以下表：定义、流程实例、节点实例、泳道、动作实例、回退记录、调度路由；另有一张片段表为预留（只有 DDL） |
| CAP-DATA-02 | 双主键口径 | 每表以自增物理主键承载声明/插入顺序，业务标识列为字符串唯一索引；对外一律只用业务键，物理主键不外露 |
| CAP-DATA-03 | 顺序即对齐依据 | 节点与动作的声明顺序必须由物理主键升序承载，运行期靠它与定义表达式按下标对齐 |
| CAP-DATA-04 | 幂等插入 | 实例行插入必须幂等（命中唯一键则忽略）；对唯一键含可空列的表，必须先按自然键查存在再插（可空列使忽略失效） |
| CAP-DATA-05 | 统一写入口 | 每张实例表必须只有一条"按需写非空列"的动态更新语句，其上的语义快捷方法不得产生新 SQL |
| CAP-DATA-06 | CAS 写 | 状态翻转必须支持带前态校验的比较交换（翻不动＝被人抢先，返回影响行数供判定） |
| CAP-DATA-07 | 桶列持久化 | 各层持久化的配置桶统一同名 `config`（流程层那份就是创建输入）；`vars`、`result` 各自成列；一律以 JSON 文本存，不用数据库原生 JSON；**四张实例表都不建参数列** |
| CAP-DATA-08 | 运行期决策落位 | 控制节点的运行期决策（如分支选中哪支）必须落在该节点 config 的保留键里，不建独立列 |
| CAP-DATA-09 | 失败/跳过不落独立列 | 失败摘要与跳过原因写进 `result` 的保留键；重入时必须先摘掉上一轮残留痕迹 |
| CAP-DATA-10 | 审计列 | 每表统一创建人/更新人列：创建人＝流程创建人（外部传入），更新人由调用方从上下文显式下传（驱动期＝创建人，干预期＝操作人，无人值守＝不刷该列） |
| CAP-DATA-11 | 展示快照 | 节点/动作行的定义引用键与展示名必须物化期烙一次，让视图直接读列即可展示（匿名控制节点留空由视图回落业务键） |
| CAP-DATA-12 | 重跑观测 | 动作行必须能观测被执行的次数（落结果时自增），供幂等与重跑排查 |
| CAP-DATA-13 | 枚举持久化口径 | 所有枚举落库/比较一律用小写规范值，反查大小写不敏感；禁止按枚举原文名绑定 |

## 9 MAT 实例物化

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-MAT-01 | 两档时机 | 必须支持创建期一次建完整棵节点树（进度分母稳定）与执行到才建（默认，避免依赖运行期值的展开拿不到正确结果）；两种模式下驱动路径必须一致 |
| CAP-MAT-02 | 子层时机 | 泳道与动作行一律在驱动期按需创建（两档相同），不得在创建期预建（否则会留下永远未被执行的孤儿行） |
| CAP-MAT-03 | 类型归口 | 一种节点类型的"怎么建行"与"怎么跑"必须归在同一份类型档案里（不得拆成物化/驱动两张平行注册表，否则新增类型要成对注册、漏一边到运行期才暴露）；新增节点类型＝新增表达式 + 新增一份档案并注册，不改既有分发 |
| CAP-MAT-04 | 下标对齐 | 实例行与定义表达式必须按声明顺序两两对齐；已存在行复用、缺行用手里正在走的表达式补建（不做路径反查） |
| CAP-MAT-05 | 走查光标入行 | 对齐时必须把定义表达式、节点定义、生效监听器链挂到实例行的非持久化字段上；此后驱动与类型档案一律行内自取，不再回查定义 |
| CAP-MAT-06 | 实例只存运行期数据 | 可由"钉死版本的定义"推导的信息（监听器链、拓扑）不得落实例表；展示用快照是唯一例外 |
| CAP-MAT-07 | 生效策略冻结 | 节点行的错误策略必须在物化期落**生效值**（自己声明 > 流程级全局 > 默认），泳道继承所属节点 |
| CAP-MAT-08 | guard 冻结 | 节点级 guard 必须物化期落进实例行，使恢复路径不依赖定义即可判定 |
| CAP-MAT-09 | 半物化愈合 | 崩溃或异常导致只建了一部分行时，重新驱动必须按需补齐缺行，且不重复建、不改变已有拓扑顺序 |

## 10 DRV 驱动与调度

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-DRV-01 | 流程级认领 | 启动必须先比较交换把流程从待执行翻执行中，取得唯一驱动权；抢不到不报错，只回报当下状态 |
| CAP-DRV-02 | 单 owner 递归驱动 | 一个流程由一个 owner 走查驱动整棵树；流程内并发用 owner 自己的池铺开 |
| CAP-DRV-03 | 前向走查 | 顶层必须按"前置 → 主流程 → 收尾"顺序驱动；收尾具备 finally 语义（无论成败都执行，其结果参与终态聚合；handler 让渡轮除外：退出不跑，重入完成后再收尾） |
| CAP-DRV-04 | 幂等重入 | 已落终态的节点行、已落终态的动作行在重入时必须直接跳过，不再触发监听器与类型档案（非终态的动作行属让渡/中断残留，重入重跑，至少一次）——这就是断点续跑的全部机制，不得引入第二套恢复语义 |
| CAP-DRV-05 | 类型分发 | 四类节点（动作/并行/条件/聚合）各有一份类型档案；物化按表达式类分发、驱动按行上类型分发，两处分发必须同源（一次注册）；类型不识别要明确报错，同一类型被两份档案认领要在装配期就拒绝 |
| CAP-DRV-06 | 递归解耦 | "如何驱动一棵子树/一个容器内的动作序列"必须由独立的驱动器承载，类型档案与引擎互不在构造期相互依赖（协作走方法参数回调，避免环） |
| CAP-DRV-07 | 条件分支 | 条件必须支持 then 与可选 else；选中哪一支必须持久化，恢复时复用不重算；未选中分支不物化；无分支可走时判为跳过（控制流上等价成功） |
| CAP-DRV-08 | 容器扇出 | 并行容器子项、分片泳道、容器内动作序列都必须能串/并行两档执行，并行一律扇出到对应档的池并 join 聚合；串行走查（闸门→定位驱动→聚合→收敛）与并行汇聚（join→异常算失败→失败即取消未开始项）的骨架必须单一定义，各层只显式声明自己的差异（收敛依据、是否设取消闸门、剩余项副作用），不得逐层各抄一份 |
| CAP-DRV-09 | 池满不饥饿 | 并发池满时必须由提交方线程自跑（背压），不得出现 owner 线程 hold 等待子任务造成假死 |
| CAP-DRV-10 | 主动调度 | 必须提供后台轮询认领待执行流程的调度器：按池剩余容量限量认领、批量捞取、认领后异步驱动；可禁用改为同步触发 |
| CAP-DRV-11 | 分布式路由 | 调度必须支持按"服务单元 + 可选网络区域"过滤认领范围；未路由的流程不被主动认领（仍可同步触发）；无路由配置时保持全局捞取的老行为 |
| CAP-DRV-12 | 崩溃归属 | 单 owner 模型下 owner 进程崩溃会留下执行中的僵持流程，必须由人工干预（重试）翻回可认领态；租约/心跳作为预留能力 |
| CAP-DRV-13 | 让渡与重入 | 动作处理器返回过程态（待重入/暂停/挂起）时本轮必须立即退出：状态原值落库等重入、收尾段与后续根不跑、剩余项不 drain、容器不落终态、不发收尾监听；重入时终态行跳过、非终态行重跑（至少一次）；待重入由调度重捞、暂停走恢复入口、挂起停驻；坏终态（失败/停止）优先于让渡 |

## 11 POL 错误策略与收敛

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-POL-01 | 两档策略 | 必须支持快速失败与失败继续两档，默认快速失败 |
| CAP-POL-02 | 流程级全局声明 | 流程级声明一次即对所有未自行声明的节点（含匿名控制节点与其泳道）生效 |
| CAP-POL-03 | 就近覆盖 | 节点（含命名容器）自己的声明优先于全局；单值语义为覆盖，不像监听器链那样拼接 |
| CAP-POL-04 | 序列收敛就近优先 | 顶层根序列与组内序列遇坏是否叫停：坏的那一项自己声明过就听它的，没声明才回落本层策略；**容器内部收敛只看容器那一条，子项声明不得跨层** |
| CAP-POL-05 | drain 语义 | 快速失败不得强行中断已在跑的任务：只取消尚未开始的排队项，等全部结束后聚合失败；串行则停止发起后续项并把已建未跑的行标为停止 |
| CAP-POL-06 | 终态聚合 | 容器/流程终态必须按严重程度取最差：失败 > 停止 > 成功/跳过；跳过与成功都算完成且不拦后续；让渡感知：坏终态优先 > 让渡 > 严重程度（退让信号不得被吞成成功） |
| CAP-POL-07 | 取消闸门单点 | 取消判断必须只认流程实例状态这一份真值，驱动路径每步当场读库；引擎不得持有本机取消状态或缓存 |
| CAP-POL-08 | 业务自愿收敛 | 必须向长循环业务暴露取消位（动作上下文上置，不查库），由业务自行收敛，框架不强中断 |
| CAP-POL-09 | 自动回退 | 流程级开关打开后，本次驱动终态为失败或停止时必须在收尾（落终态 + 发完流程收尾监听器）之后自动补一轮逆序补偿；暂停不触发；回退异常不得改写调用方拿到的终态 |

## 12 SHD 分片

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-SHD-01 | 声明即分片 | 节点声明分片解析器名即成为分片节点；一个分片键对应一条泳道，泳道是动作的容器 |
| CAP-SHD-02 | 两阶段解析 | 必须分两阶段：解析全部分片键（驱动期现解，每次可重解，要求幂等稳定）+ 按分片键现场重建强类型负载（不落库） |
| CAP-SHD-03 | 解析器入参 | 分片解析必须以节点上下文为入参：节点级 config 与定义在本层读，流程级变量/创建输入沿父链上溯，于是同一解析器被多节点复用时各拿各的参数 |
| CAP-SHD-04 | 泳道物化时机 | 泳道必须走查到达才建（串行）或扇出前补齐（并行），按节点 + 分片键幂等复用 |
| CAP-SHD-05 | 泳道并发档 | 必须支持泳道串行与并行两档（默认串行），并行扇出到分片专用池 |
| CAP-SHD-06 | 空集合语义 | 分片键解析出空集合时该节点静默判成功（要表达"没有分片就是失败"必须由业务在解析器里抛异常） |
| CAP-SHD-07 | 作用域即执行范围 | 分片键集合就是本节点的执行范围；分片只发生在叶子节点，容器节点不得带分片 |

## 13 CTX 上下文与数据交接

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-CTX-01 | 两级读法 | 必须区分"本层直取单键"（平铺精确命中，不上溯不上钻）与"沿父链上溯解析"（支持点号下钻）；不得提供跨三桶合并的模糊读取 |
| CAP-CTX-02 | 泛型读取 | 按 key 读取必须返回调用点推断的类型，类型不符在调用点当场失败，不后漂 |

| CAP-CTX-07 | 定义只读可达 | 流程上下文必须挂载钉死版本的定义，使监听器在前置切点就能读到全量拓扑与节点配置（不必等实例行） |
| CAP-CTX-08 | 变量不收空值 | 变量桶不接受空值：写了但留空的键视为不存在，显式写空值等于删键 |

## 14 VAR 占位符与条件

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-VAR-01 | 保留作用域集合 | 只有以保留首 token（变量/参数/配置/结果 + 四个锁定层级）开头的占位符才由引擎解析；其余一律视为业务自己的模板语法，原样保留、不报错、不定罪 |
| CAP-VAR-02 | 上溯与锁定 | 桶级写法必须本层优先沿父链上溯；层级锁定写法只读那一层的本桶 |
| CAP-VAR-03 | 两档时机 | 必须支持物化期解析（用创建期初始变量，结果桶与配置桶留待运行期）与激活期解析（读运行期实时变量与结果）两档 |
| CAP-VAR-04 | 物化即定型 | 占位符的语义必须在物化时刻定型：物化期解得出就烙成字面量（此后变量变化不回溯影响该行），解不出就退化为活引用每次现取 |
| CAP-VAR-05 | 间接键选支 | 必须支持占位符路径里再嵌占位符（由内向外先插值再取值），以此表达"按运行期值挑一份片段"；引擎不得内置任何业务保留键名 |
| CAP-VAR-06 | 部分解析固化 | 指针变量有值但外层取不到值时，必须回写已插值的路径（指针在解算那一刻固化），不再依赖指针变量后续变化 |
| CAP-VAR-07 | 递归有界 | 取到的值本身是模板时只再填一轮，且内层不再插值不再二次填值——链条深度恒定，自引用不得递归成环 |
| CAP-VAR-08 | 残留可见 | 必须能列出"引擎该解却没解出来"的残留路径（只报保留写法），供告警与实例行留痕，使静默失配变可见 |
| CAP-VAR-09 | 条件求值 | 必须内置轻量求值：等于/不等/大小比较、与或非、括号分组、带引号字面量、数值优先否则字符串比较；空表达式判真 |
| CAP-VAR-10 | 求值铁律 | 条件只能读已持久化的桶（保证恢复确定性）；未解析的引擎占位符必须整条判假并告警，外来模板按字面量比较 |
| CAP-VAR-11 | 求值器可替换 | 求值实现必须可被替换成更强的表达式引擎（保持接口不变） |

## 15 OBS 监听器与观察者

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-OBS-01 | 四类声明式监听器 | 必须支持流程级 / 节点级 / 动作级 / 回退级四类监听器，各自只收本层上下文类型（类型即作用域，编译期不可混用） |
| CAP-OBS-02 | 两切点 | 每类只有前置与收尾两个切点：前置抛异常＝否决（流程失败/整节点失败/整动作失败/整轮回退不执行），收尾＝纯通知且吞掉异常 |
| CAP-OBS-03 | 声明顺序 | 监听器声明只有名字与配置两项，执行顺序＝声明顺序（不得有排序字段） |
| CAP-OBS-04 | 全局链 | 必须支持"声明一次、对每个节点/每个动作都生效"的全局节点级与全局动作级链，与各层本地链合并时全局在前、不去重 |

| CAP-OBS-07 | 切点次序 | 必须固定次序：观察者前置 → 监听器前置 → 实际执行 → 监听器收尾 → 观察者收尾 |
| CAP-OBS-08 | 业务 SPI 注册 | handler 与四类监听器必须以 Spring Bean 自动注册、按名字路由：**重名注册必须拒**、取用不到必须明确报错；分片解析器同样按名字路由（重名拦截现状见 GAP-08）；观察者不设名字与配置，全量遍历、按注册次序执行 |
| CAP-OBS-09 | handler 契约 | 动作处理器必须只返回状态（返回空视为成功，抛异常视为失败；返回过程态（待重入/暂停/挂起）＝让渡退出等重入，重入重跑——至少一次），结果由业务自己写进上下文桶；契约是至少一次执行，**必须幂等**；条件跳过用声明式 guard 而非 handler 内动态跳转 |

## 16 ERR 异常与失败留痕

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-ERR-01 | 统一异常类型 | 引擎侧抛出必须统一为携带消息键与可变参数的运行时异常，调用方可按码分支而不按文案匹配 |
| CAP-ERR-02 | 码区间分区 | 消息键必须占用固定区间并按功能域分段（解析/装载/物化驱动/计划缓存/求值/注册表/JSON/业务键），一个键一条文案、参数按位填充 |
| CAP-ERR-03 | 文案解不出不抛 | 键缺失、文案源异常、参数格式异常都必须降级为"键 + 参数"，绝不因取文案二次异常 |
| CAP-ERR-04 | 摘要带码 | 异常的文本形态必须让消息键可见（类型统一后靠码定位错误种类） |
| CAP-ERR-05 | 一句可读摘要 | 引擎每层捕获的异常必须收成"语境(定位): 类名: 消息"一句，并先拆掉并发包装类 |
| CAP-ERR-06 | 分层留痕 | 动作行与节点行各记自己那条摘要；流程行只记本次驱动的**首条**（并行同炸只留最先那句） |
| CAP-ERR-07 | 留痕入库与摘除 | 坏终态才把流程级摘要落库，好终态必须反向摘掉上一轮残留；定义都取不出这类"还没铺开就失败"的路径也必须兜底落库并翻终态，不能让流程僵在执行中 |
| CAP-ERR-08 | 门面捎带原因 | 执行类入口必须能在坏终态时顺带回传那一条摘要（成功路径不多查库），完整明细仍走进度接口 |

## 17 INT 干预与恢复

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-INT-01 | 暂停/恢复 | 必须能把执行中的流程置暂停（在跑的收敛、未跑的不发），并能翻回待执行重新入队（已完成项重入跳过；handler 让渡到暂停态的流程走同一恢复入口） |
| CAP-INT-02 | 停止 | 必须能把执行中或暂停的流程置停止；只翻闸门，不强中断 |
| CAP-INT-03 | 整轮重试 | 必须支持以流程实例为发起单位的重试：扫完整棵实例树，把"本轮没跑成"的行（失败/停止/卡途中）复位，容器链与闸门随之翻回可认领，重入即从断点续跑到结尾 |
| CAP-INT-04 | 复位口径 | 成功与跳过不得复位（既成事实 + 人工干预结论）；闸门不允许重跑的成功/跳过流程必须返回失败，不把跑成功的流程再跑一遍 |
| CAP-INT-05 | 无事务下的安全顺序 | 干预写库必须"先判资格（翻不动闸门就一行不碰）+ 闸门最后翻"，中途异常时流程尚未进入可被捞起的状态；且整段必须可重复调用补完 |
| CAP-INT-06 | 定点重跑 | 必须保留按单条动作复位重跑的细粒度入口（复位该动作并沿祖先容器链复位、流程重新入队） |
| CAP-INT-07 | 人工跳过 | 必须能把卡住或失败的动作置跳过并让流程继续推进（留跳过原因） |
| CAP-INT-08 | 复位不动结果 | 干预复位状态时不得清掉业务结果桶内容（结果要留给重跑与排障参考），残留痕迹由驱动侧本轮摘 |
| CAP-INT-09 | 审计到人 | 每次干预改过的行必须以操作人作为更新人，回退发起人在回退记录里同样可查 |

## 18 RBK 回退与补偿

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-RBK-01 | 逆序补偿 | 必须对"已成功且声明可补偿"的动作按执行逆序调用补偿逻辑 |
| CAP-RBK-02 | 不可补偿即停 | 遇不可补偿的步骤必须停止并留阻塞记录告警（不得跳过它继续拆前面的） |
| CAP-RBK-03 | 补偿失败即停 | 补偿自身异常必须记失败并停止，不无限重试、不外抛给调用方 |
| CAP-RBK-04 | 不重复撤销 | 已成功补偿过的动作必须跳过（判据是回退历史里最新一条已补偿）——重复撤销通常比漏撤更糟 |
| CAP-RBK-05 | 历史独立留痕 | 每个补偿步骤必须单独一行历史记录（关联原动作），不得回写原动作实例的状态（它是不可变的执行事实）；补偿态机：进行中 → 已补偿/补偿失败/阻塞 |
| CAP-RBK-06 | 现场重建 | 补偿路径必须以实例行重建上下文（含分片负载现场重建与激活期占位符解析），使补偿能读到运行期写入的值与回退前置现取的现场信息 |
| CAP-RBK-07 | 回退专用切点 | 补偿不走正常驱动路径，因此必须为回退单独提供前置/收尾一对切点：前置可否决整轮（一条都不补）、收尾只收聚合结果 |
| CAP-RBK-08 | 凭据不落库 | 回退前置挂进流程级结果桶的现场信息必须只活在内存（回退路径不刷该列） |
| CAP-RBK-09 | 人工发起 | 必须提供"发起回退请求（翻闸门）+ 执行回退（返回报告）"两步入口；报告必须能区分已补偿/阻塞/失败/跳过与否决原因，并给出聚合结果 |
| CAP-RBK-10 | 与重试衔接 | 回退后再重试必须能恢复现场（当前实现：重放未落地，见 GAP-02） |

## 19 API 对外接口

| 编号 | 能力 | 要求 |
| --- | --- | --- |
| CAP-API-01 | 单一门面 | 必须以一个门面类对外提供全部能力（计划、执行、干预、进度、回退的组合），业务键一律字符串 |
| CAP-API-02 | 创建与执行分离 | 必须支持"只创建不执行"（等调度接手）与"创建并立即执行"两类入口，后者为可选带路由标签的重载 |
| CAP-API-03 | 执行返回口径 | 带执行的入口必须返回"实例 id + 调用结束时的状态（坏终态附一条失败摘要）"，不承诺一定是终态、不造假状态、查不到行即空状态 |
| CAP-API-04 | 不暴露持久化行 | 对外返回不得是持久化实体行（物理主键不外露、裸 JSON 不让调用方自解析、可变对象不外抛） |
| CAP-API-05 | 流式语法糖 | 必须可选地提供链式构建入口（版本、创建人、路由、参数逐段填充，末尾只创建或创建并执行），且**不新增任何引擎语义**：空参数等价传空、键名不做点号展开、一次性非线程安全 |
| CAP-API-06 | 干预入口 | 干预类入口一律返回是否真的生效（布尔），回退返回报告，查询返回结构 |
| CAP-API-07 | REST 入口 | 必须提供创建（可选自动启动）、启动、暂停、恢复、停止、回退、重试（流程级与动作级）、跳过、进度的 HTTP 端点；操作人作为参数缺省为系统 |
| CAP-API-08 | 会话自理 | 引擎必须不管用户会话：创建人由调用方取好传入，干预操作人显式传；无线程本地上下文 |
| CAP-API-09 | 向后兼容 | 语法糖与新增返回类型不得改变既有方法签名与行为；老调用方照旧 |

## 23 GAP 现状与承诺不一致（生成时必须显式处置）

| 编号 | 不一致之处 | 处置要求 |
| --- | --- | --- |
| GAP-01 | 调度器没有被装配：配置类里创建调度器的方法**未标注为 Bean**，且组件扫描包含一个不存在的包 | 生成时必须二选一：把调度器纳入装配（并声明开关），或彻底移出配置类改由宿主显式注册；扫描包清单必须与实际包结构一致 |
| GAP-02 | 门面与注释承诺"回退后重试会先把被撤销的副作用按执行顺序**重放**回来"，代码中无重放组件；回退状态机也只实现了补偿四个态（重放三态仅出现在 DDL 注释） | 重放属**未实现能力**：需求上应作为独立扩展项排期，或在门面注释与文档中删除承诺；不得在按本清单生成代码时"顺手补出"一个来源不明的重放器 |
| GAP-03 | 泳道表有配置与结果列，注释称"同分片键共享上下文"，但引擎只写状态、从不写这两列 | 生成时要么补上泳道级桶的落库路径（并与桶隔离口径一致），要么删列/改注释；不得保留"看起来能写其实没人写"的假能力 |
| GAP-04 | 示例定义里用了 `${lane.shardKey}`，但解析器对锁定层只支持四个桶，该写法解不出（会被当作残留告警并原样传给业务） | 示例必须改写为可用写法（如分片负载由 `shardPayload()` 取，或创建参数走 `${config.*}`）；若确实要支持层内非桶字段，则属 DSL 扩展需显式立项 |
| GAP-05 | 配置类注释与代码不符：注释称数据源工厂 Bean 名为 `orchestratorSqlSessionFactory`、扫描包为 `com.orchestrator.mapper`，实际 Bean 名是 `processSqlSessionFactory`、扫描包是引擎自身的 mapper 包 | 注释须与真实 Bean 名、真实包名逐字对齐（Bean 名是宿主契约，宿主按注释去覆盖会覆盖不掉） |
| GAP-06 | 构建清单里存在与引擎无关的第三方 `pom` 型依赖 | 生成新构件时不得继承该无关依赖；依赖清单应限于第 21 节所列 |
| GAP-07 | 分片负载"默认原对象直取、显式给类型才做转换"这一档差别只体现在方法重载，容易被误用 | 接口文档必须写明：常态不要传目标类型参数（避免不必要的序列化转换） |
| GAP-08 | 分片解析器注册表当前**不拦同名重复注册**（后注册的静默覆盖前一个），而 handler 与三类监听器的注册表都会当场拒 | 必须统一口径：要么补上重名拒绝（与其余注册表一致），要么在文档写明"分片器同名允许覆盖"；不得留两套相反的注册契约 |

## 24 对外不可变契约（附录，必须逐字一致）

以下是**跨版本、跨宿主**的外部契约，命名可以变（类名/文件布局自由），这些值不能变：

| 类别 | 契约内容 |
| --- | --- |
| 表 | 前缀派生的八张表：定义、实例、节点实例、泳道、动作实例、回退记录、片段（预留）、调度 |

| 状态字面量 | 运行态九值（小写文本），终态四值；严重程度次序：失败 > 停止 > 成功/跳过；让渡三态（待重入/暂停/挂起）可作处理器返回值落流程行，聚合口径为坏终态 > 让渡 > 严重程度 |
| 发布态 | 草稿 / 已发布 / 已归档 |
| 节点类型 | 并行 / 条件 / 聚合 / 动作（循环预留） |
| 错误策略 | 快速失败 / 失败继续（默认前者） |
| 补偿态 | 进行中 / 已补偿 / 补偿失败 / 阻塞（重放三态属预留） |

| 占位符保留首 token | 变量、参数、配置、结果 + 流程/节点/泳道/动作四层锁定前缀 |

| YAML 段名 | 物化时机、变量、流程、前置、收尾、四类监听器段、两个全局链段、错误策略、自动回退、节点表 |

## 25 用这份清单做什么

1. **做设计**：以第 3 节的域为单位划分模块与职责边界；先落第 2 节概念模型（同形、隔离、上溯三件事定错，后面全错）。
2. **生成代码**：按 4 → 21 的顺序生成（装配 → 定义 → 校验 → 缓存 → 数据 → 物化 → 驱动 → 策略 → 分片 → 上下文 → 解析 → 监听 → 异常 → 干预 → 回退 → 接口 → 视图 → 非功能）；每域生成后立即核对该域表格，**任何一行无法对应到实现或测试即视为未完成**。
3. **守住不做清单**：第 22 节列的东西一律不生成。
4. **处置偏差**：第 23 节每条 GAP 必须在设计说明里写明"补齐 / 删除承诺 / 立项"三选一的结论，不得静默选边。
5. **回归基线**：改动引擎时按编号回归；新增能力必须在本文登记一行（域 + 编号 + 一句话要求），并把可验证的刚性值补进第 24 节或配套细规。
